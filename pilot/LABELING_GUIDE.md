# 열화상 수배전반 라벨링 기준서 (1인 작업용)

이 문서는 혼자 지속적으로 라벨링할 때 **매번 같은 판단을 내리기 위한** 규칙이다.
작업자 간 일치도가 아니라 **자기 자신과의 일치도**가 목표다.

가장 중요한 원칙 하나:

> **이미지에서 확인할 수 없는 것은 라벨링하지 않는다. 추측해서 붙인 라벨 하나가
> 확실한 라벨 여러 개를 무력화한다.**

---

## 0. 이 작업의 목적

부품 종류를 맞히는 것이 목적이 아니다. **박스 안 화소에서 온도를 집계해 이상 발열을
찾는 것**이 목적이다. 그래서 일반 객체탐지 라벨링과 두 가지가 다르다.

1. **박스 경계가 판정 결과를 바꾼다.** 배경이 많이 들어가면 박스 온도가 희석된다.
2. **상(相)별로 따로 그려야 한다.** 같은 부품의 R·S·T 를 비교해 판정하므로,
   3상을 한 박스로 묶으면 판정 자체가 불가능해진다.

---

## 1. 클래스 정의

### 변압기 (transformer)

- 전압을 변성하는 본체. **MOF 계열 반에서는 거의 나오지 않는다** (전력용 변압기는
  보통 TR반에 있다).
- PDF 기준: 접촉부(부싱)에 연결된 **선이 1개**.
- **IR 단독으로 이 기준을 확인할 수 없으면 라벨링하지 않는다.** 아래 3항 참조.

### 변류기 (ct_transformer)

- 전류를 계측용으로 변성하는 기기. MOF 반의 주 대상.
- PDF 기준: 접촉부에 연결된 **선이 2개**.
- 실제 데이터에서는 **형태가 두 종류**로 관측된다.
  - 애자(부싱)형 — 주름 애자가 여러 개 서 있는 형태
  - 상자형 — 명판이 붙은 사각 몸체
  둘 다 변류기로 라벨링하되, **어느 쪽인지 reason 에 기록**한다.

### 접촉부 (…_contact)

- 부품과 도체가 **볼트로 체결된 지점**. 열화가 가장 먼저 나타나는 곳이다.
- 범위는 **체결 볼트와 러그까지**. 케이블이 뻗어 나가는 부분은 포함하지 않는다.
- 상별로 따로 그린다.

---

## 2. bbox 규칙

| 항목 | 규칙 |
|---|---|
| 범위 | 부품 외곽에 딱 맞춘다. 벽·바닥·빈 공간을 물지 않는다 |
| 프레임 가림 | 구조 프레임이 가로질러도 **한 박스로** 그린다 (나누지 않는다) |
| 3상 | 부품 1개 = 박스 1개. 3상이면 박스 3개. **절대 묶지 않는다** |
| 최소 크기 | 한 변 8px 미만이면 그리지 않는다 (온도가 노이즈) |
| 가림 | 50% 이상 보일 때만 그린다 |
| 오버레이 | 컬러바(x 302~318), 우측 숫자(y 2~27 / 212~237), 좌상단 max(0~100, 2~27), 좌하단 로고(2~58, 217~237) 위에는 그리지 않는다 |
| 대형 박스 | 프레임의 **30% 를 넘으면 재검토**한다. 물체가 아니라 영역을 그리고 있을 가능성이 높다 |

### 중복 / 겹침

- **같은 객체에 두 박스 금지.** 프레임에 갈려 보여도 하나로 그린다.
- **다른 객체 간 겹침은 허용.** 예: 변류기 본체 박스 안에 변류기 접촉부 박스가 들어가는
  것은 정상이다 (본체와 진단 포인트는 별개 대상).
- 단 **같은 클래스끼리 IoU 0.5 이상 겹치면 중복**이므로 하나를 지운다.

## 3. 애매할 때 — 보류 규칙

**이것이 이 기준서의 핵심이다.**

### 보류 판단 절차

```
1. IR 이미지만 보고 클래스를 확정할 수 있는가?
       예 → 라벨링
       아니오 → 2번
2. 같은 프레임의 실화상(RGB)에서 확인되는가?
       예 → 아래 "RGB 참고 규칙" 적용
       아니오 → 보류
```

### RGB 참고 규칙

- **RGB 는 참고용으로만 본다. 최종 라벨은 IR 좌표계에 그린다.**
- RGB 에서만 보이는 특징(명판 글씨, 케이블 색, 선 개수)으로 클래스를 정하는 것은
  **허용한다.** 다만 그렇게 정한 건은 `reason` 에 `RGB확인` 을 기록한다.
- 이유: 배포 시 모델은 IR 만 본다. RGB 로만 구분되는 특징에 의존해 라벨을 나누면
  모델은 그 구분을 배울 수 없고, 결과적으로 무작위 예측이 된다.
  **RGB확인 건이 전체의 30% 를 넘으면 그 클래스 분리는 성립하지 않는 것으로 본다.**

### 보류 처리 방법

- 박스를 그리지 않고 넘어간다.
- `out/hold_list.csv` 에 파일명과 사유를 기록한다 (`hold_note.py` 사용).
- 사유는 다음 중 하나로 통일한다.
  - `애자만보임` — 형태 특징이 안 보임
  - `해상도부족` — 너무 작거나 흐림
  - `가림` — 50% 이상 가려짐
  - `클래스모호` — 두 클래스 중 어느 쪽인지 판단 불가
  - `범위모호` — 어디까지가 한 부품인지 판단 불가

### 절대 하지 말 것

- 감으로 둘 중 하나를 고르기
- "이 반이니까 아마 변류기겠지" 하고 붙이기 → **이건 아래 4항의 반 단위 통일과 다르다.**
  반 단위 통일은 실물 확인에 근거해 **미리 정해두는 것**이고, 감으로 고르는 것은
  프레임마다 다르게 붙는다.
- 앞 프레임과 같아 보인다고 확인 없이 복사하기

## 4. 반 단위 클래스 고정 (권장)

같은 반의 같은 위치 설비는 **실물이 하나로 정해져 있다.** 사진마다 판단하지 말고
현장 확인·설비 대장으로 미리 정한 뒤 그 반 전체에 일관 적용한다.

```
예) P4-MOF&PT반 A1_B1 → 계기용 변성기는 변류기로 고정
```

이렇게 정한 내용은 `panel_policy.md` 에 기록하고, 근거(현장 확인 / 도면 / 명판 사진)를
같이 적는다. **근거 없이 정하면 안 된다.**

---

## 5. 작업 순서

```
1. 파일명의 P번호로 반을 확인한다 (A1_B1_P4_… → P4)
2. panel_policy.md 에서 그 반의 고정 클래스를 확인한다
3. IR 을 본다. 확정 가능하면 그린다
4. 애매하면 RGB 를 본다
5. 그래도 애매하면 보류하고 사유를 기록한다
6. 한 세션을 끝낼 때마다 보류 목록을 훑어 패턴을 찾는다
   같은 사유가 반복되면 그건 개별 판단 문제가 아니라 클래스 정의 문제다
```

## 6. 자기 일치도 점검 (혼자 작업할 때의 품질 관리)

작업자가 한 명이면 교차검증을 못 하므로, **시간차 재라벨링**으로 대신한다.

```
1. 각 세션에서 무작위 10장을 따로 보관한다 (recheck set)
2. 세션을 다 끝낸 뒤 최소 하루 지나서 그 10장을 다시 라벨링한다
3. python selfcheck.py 로 1차와 2차를 비교한다
```

합격선:

- 판정 일치율 ≥ 90% (같은 사진에서 같은 이상 등급이 나오는 비율)
- matched IoU 중앙값 ≥ 0.70
- 박스 개수 차이 ≤ 10%

미달이면 그 세션은 기준이 흔들린 것이므로 재작업한다.

장비나 해상도가 생기면 다시 볼 대상이다.
