Note
항목별 정확한 박스 경계(포함/제외 픽셀 범위)는 v2 가이드의 반별 상세 사진과 색상 스와치를 1차 기준으로 삼는다. 이 표는 어떤 항목을 가공하고 어떤 항목을 제외하는지를 정리한 것이며, 픽셀 단위 경계 규칙 문서는 4단계(시드셋 라벨링) 착수 전 별도로 확정한다.
라벨링 제외 규칙 (Negative / Ignore)
  • 부스바·케이블·ACB 접촉부는 v2 기준 항상 제외 — 패턴이 일정하지 않거나 구조상 잘 보이지 않아 탐지 정확도가 낮음
  • 철심부·인입선로 접촉부·CT 접촉부·MCCB 접촉부는 주의(⚠️) 대상 — 위치·반사·구분 곤란 문제로 미검출/오검출이 잦으므로, 보일 때만 라벨링하고 판별이 어려우면 판별 불가로 미라벨 처리한다 (없다고 단정해 정상으로 넘기지 않는다)
  • 너무 작아서 부품 종류를 식별할 수 없는 경우 — 박스 생략
  • 다른 부품에 완전히 가려져 형태를 확인할 수 없는 경우 — 박스 생략
  • 프레임 밖으로 잘린 경우 — 해당 부품의 정상 촬영 시 전체 면적 대비, 화면에 노출된 영역이 30% 미만(= 70% 이상 잘림)이면 박스 생략. 30% 이상 노출되어 있으면 남은 영역만 박스 치고 truncated로 표기
  • 동일 부품이 겹쳐 개별 경계를 구분할 수 없는 경우 — 그룹 박스로 묶지 않는다. 현재 단계에서 그룹 박스는 허용하지 않으며, 개별 경계를 식별할 수 없으면 Ignore 처리(라벨링 제외)한다
Note
프레임 밖으로 잘린 부품은 truncated 속성을 붙이고, 이미지마다 클로즈업 / 중거리 / 전체 촬영 여부를 메타데이터로 태깅한다. truncated(프레임 밖 잘림) · occluded(다른 부품에 가려짐) · ignore(판별/경계 불가)는 서로 다른 속성이므로 라벨링 툴에서 별도 필드로 구분해 기록한다.
02

Raw 데이터 전처리 파이프라인 구축

radiometric 데이터를 추출(exiftool, flyr/flirpy 등)하고, 재질별 emissivity 차이를 활용한 에지 강조 이미지를 생성한다.

Note
기울어진 사진이 많다면 패널 외곽선을 기준으로 한 자동 회전 보정(Hough 변환 등)을 이 단계에 포함시켜, 이후 박스 정밀도 문제를 근본적으로 줄인다.
03

중복·유사 이미지 제거

완전히 동일한 프레임은 퍼셉추얼 해시(pHash)로 걸러내고, 같은 패널을 다른 점검 회차에 찍은 것처럼 미세하게만 다른 근접 중복은 이미지 임베딩 코사인 유사도로 클러스터링한다. 클러스터별 대표 이미지만 라벨링 대상으로 남긴다.

Note
같은 클러스터의 이미지가 train/val에 나뉘어 들어가면 검증 지표가 부풀려지는 data leakage가 생긴다. 이후 데이터 분할은 반드시 클러스터 단위로 나눈다.
04

소규모 시드셋 직접 라벨링

중복 제거 후 남은 대표 이미지 중 300~500장을 사람이 직접 라벨링한다. 클래스별 최소 30~50개 인스턴스를 확보하되, 클로즈업/중거리/전체 샷이 골고루 섞이도록 구성한다. RGB 페어 이미지가 있다면 RGB에서 라벨링 후 좌표를 열화상으로 투영한다.

Note
30~50개는 시드셋 확보를 위한 초기 최소치이며, 최종 학습 데이터셋의 목표 인스턴스 수가 아니다. 최종 목표치는 08~09단계에서 클래스별 성능(예: mAP)을 확인한 뒤 별도로 정한다.
05

라벨러 간 일치도 검증

시드셋 일부를 2인 이상이 독립적으로 라벨링한 뒤 mIoU 등으로 일치도를 계산한다. 샷 타입별로 골고루 샘플링해 검증해야, 특정 촬영 유형에서만 가이드라인이 흔들리는지 확인할 수 있다.

06

베이스라인 detector 학습

시드셋으로 YOLO 계열 등 가벼운 객체 탐지 모델을 빠르게 학습시킨다. 이 모델이 이후 대량 데이터에 대한 사전 라벨 생성기 역할을 한다.

07

전체 데이터셋 자동 사전 라벨링

베이스라인 모델로 나머지 대표 이미지에 박스를 자동 생성한다. 사람은 처음부터 그리지 않고 틀린 부분만 수정한다.

Note
전체 촬영 이미지는 부품이 작게 나오므로, 타일(patch) 단위로 잘라 추론하는 SAHI류 기법을 함께 적용해 작은 객체 누락을 줄인다.
08

Active Learning 반복 검수

모델 확신도가 낮은 샘플, 그리고 특정 샷 타입(예: 전체 촬영)에서 오류가 몰리는 경우 해당 유형 위주로 우선 검수하고 필요하면 재학습한다.

09

최종 검수·문서화

자동 라벨 대비 수정 비율, 일치도 수치, 샷 타입별 성능 편차, 클래스별 인스턴스 분포, 경계·촬영유형·중복제거 가이드라인 문서를 정리해 라벨링 결과의 근거 자료로 남긴다. raw 온도 배열 참조와 중복 클러스터 매핑도 함께 보관해, 이후 대표 이미지 라벨을 나머지 클러스터 멤버에 전파하거나 핫스팟 단계에서 재사용한다.

참고 기준선 — 유사 도메인(산업설비 열화상 객체탐지) 국가 공인 데이터셋의 통과 기준은 mAP@IoU 0.5 = 70%였고 실측은 83.8%였다. 본 프로젝트는 부품 단위까지 세분화된 더 정밀한 라벨링이므로, 이 수치를 하한선으로 삼고 그 이상을 목표로 한다.
04 Next Revision — Hotspot Labeling: Method Comparison Design

핫스팟(열점) 상태 라벨링은 사람이 직접 그리는 방식이 아니라, 아래 세 가지 반자동 방법을 동일한 정답셋에 대해 실행하고 정확도·처리시간·사람 개입 비율·오류 분포를 수치로 비교해 최적 방식을 채택한다. 결과 수치는 위 Quality Evidence 섹션과 같은 형식으로 보고서에 반영한다.

정답셋(Ground Truth)은 기존에 이미 라벨링된 데이터를 재사용한다 — 단, 8개 반 기준과의 일치 여부·라벨 분포·raw 온도 배열 보존 여부를 우선 검증한다. ①번(규칙 기반)은 raw radiometric 데이터가 없으면 실행이 불가능하다.
세 가지 방법 실행 절차

규칙 기반 사전 라벨링

raw 온도 배열에서 반별 판정 기준(임계값·패턴)을 코드화 → 정답셋 이미지 전체에 자동 라벨 일괄 생성. FLIR 등 장비의 정상/대기/재검사/이상 자동 판정 로직과 동일한 원리.

Active Learning

정답셋 중 시드 일부로 베이스라인 모델 학습 → 나머지 예측 → confidence 하위 샘플만 사람이 검수(시뮬레이션) → 재학습. 반복 횟수는 실행 단계에서 확정.

클러스터링

온도 히스토그램·핫스팟 위치 특징으로 비지도 클러스터링 → 클러스터별 대표 1장만 라벨링했다고 가정 → 나머지에 라벨 전파.

측정 지표
지표계산 방법의미
정확도자동/전파 라벨 vs 정답셋 일치율방법별 신뢰도
처리 시간코드 실행 시간 + 사람 검수 시간방법별 속도
사람 개입 비율직접 확인·수정한 데이터 비율인건비 절감 효과
오류 분포오분류 건수를 반·부품별 집계방법별 취약 지점
비교 실행 순서
  1. 정답셋 확보 — 기존 라벨링 데이터 검증 (기준 일치·라벨 분포·raw 데이터 보존)
  2. ①②③ 각각 독립 실행 — 동일 정답셋 이미지에 대해 예측 라벨 생성
  3. 정답셋 대조 — 4개 지표(정확도·시간·개입비율·오류분포) 산출
  4. 표·그래프 비교 — 세 방법을 나란히 정리
  5. 조합 시나리오 실행 — ①로 1차 자동 라벨 → ②로 애매한 것만 검수 → ③으로 중복 제거
  6. 최종 통합 — 순수 방법 3개 + 조합 시나리오, 총 4개 결과를 하나의 비교표로 정리
Expected Outcome

실무 적용은 통상 세 방법의 조합(①→②→③)이 단일 방법보다 정확도·속도 균형이 가장 우수할 것으로 예상되나, 이는 가정이며 실측 후 최종 채택 방식을 확정한다. 최종 결과는 위 Quality Evidence 섹션의 벤치마크 형식(기준값 vs 측정값)으로 정리해 mAP@IoU 0.5 = 70% 하한선과 함께 보고서에 반영한다.

05 Execution Guide — 실행 절차

위 비교 설계를 실제로 착수할 때 필요한 준비물·단계별 소요시간·산출물을 정리했다. 담당자가 바뀌어도 이 표만으로 재현 가능하도록 구성한다.

사전 준비 체크리스트
  • 정답셋 원본 위치 확인 — 기존 라벨링 데이터(200~300장)의 이미지 파일·라벨 파일·raw 온도 데이터(있는 경우) 경로를 하나로 정리
  • 라벨 기준 일치 여부 검토 — 기존 라벨링 시점의 반 기준과 현재 8개 반 가이드가 동일한지 대조, 다르면 해당 항목만 재검수
  • raw radiometric 데이터 보존 여부 확인 — ①번(규칙 기반) 실행 가능 여부를 좌우하므로 가장 먼저 확인. 없으면 ①번은 JPEG 기반 근사 규칙으로 대체하거나 실험에서 제외
  • 실행 환경 준비 — Python 환경, 필요 라이브러리(온도 데이터 추출: exiftool/flirpy, 클러스터링: scikit-learn, 모델 학습: 사용 중인 detection/classification 프레임워크)
단계별 실행 계획
단계작업 내용산출물예상 소요
0. 준비 정답셋 정리, 기준 일치 검토, raw 데이터 유무 확인 ground_truth/ 정리 폴더 0.5~1일
1. 규칙 기반 ① 반별 임계값·패턴 규칙 코드화 → 정답셋 전체 자동 라벨 생성 rule_based_labels.csv 1일
2. Active Learning ② 시드 학습 → 예측 → 저확신 샘플 검수(시뮬레이션) → 재학습 반복 al_labels_round{n}.csv, 반복별 정확도 로그 2~3일
3. 클러스터링 ③ 온도 히스토그램·핫스팟 특징 추출 → 클러스터링 → 대표 라벨 전파 cluster_labels.csv, 클러스터 시각화 1일
4. 지표 산출 3개 방법 각각 정확도·시간·개입비율·오류분포 계산 지표 비교표(raw) 0.5일
5. 조합 시나리오 ①→②→③ 순서로 결합 실행 후 동일 지표 산출 조합 결과 지표 1일
6. 정리·보고서 4개 결과 통합 비교표·그래프 작성, Quality Evidence 형식으로 문서화 최종 보고서 섹션 1일
진행 중 확인 포인트
  1. 0단계 완료 즉시 raw 데이터가 없다고 판단되면 ①번을 실험에서 제외하고 ②③ 두 방법만으로 설계를 축소 — 이 결정은 늦어도 1일차에 확정
  2. 1~3단계는 병렬 진행 가능 — 서로 독립적인 파이프라인이므로 인력이 있다면 동시 착수해 전체 기간 단축
  3. 2단계(Active Learning) 반복 횟수는 실행 중 정확도 개선폭이 둔화되는 지점에서 조기 종료 가능 — 최대 반복 수는 사전에 상한만 정해두고 유연하게 운용
  4. 4단계 지표 산출 전 세 방법의 출력 라벨 포맷(좌표계·클래스명 표기)을 통일해야 비교가 왜곡되지 않음
주의 — 정답셋을 기존 데이터로 재사용하는 만큼, 해당 데이터가 이미 어떤 모델 학습에 사용된 적이 있다면 ②번 Active Learning의 베이스라인 성능이 실제보다 높게 나올 수 있다(데이터 유출). 재사용 이력을 0단계에서 함께 확인한다.
