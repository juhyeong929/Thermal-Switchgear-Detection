# DEC-019 — 조사보다 시험 라벨링을 먼저 한다 · OQ 4건 잠정 정책

## 날짜
2026-08-28

## 결정 내용

1. **1차 시험 라벨링(30장)을 지금 착수한다.** OQ 를 전부 해소한 뒤에 하지 않는다.
2. **OQ-010 · OQ-015 · OQ-016 · OQ-017 은 닫지 않는다.** 조사 결과를 그대로 보존한 채
   *지금 무엇을 쓰고 있는가* 를 잠정 정책으로 기록한다.
3. **작업시간을 함께 기록한다.** 일치도 지표에 빠져 있던 실무 지표다.

## 무엇을 결정하지 않았는가

OSD 마스킹 여부 · 70/15/15 비율의 정당화 · 근접 미달 쌍 42.8% 의 수용 여부 ·
라디오메트릭 온도의 사용 여부. **넷 다 사람 판정 대기다.**

---

## 1. 왜 시험을 먼저 하는가

시험 착수에 남은 것은 **사람 작업뿐**이다. 30장 배포본 · 정답 은닉 · 5인 폴더 ·
`agreement.py` · `NOT_SCORED`/`FORBIDDEN`/`SKIP` 처리까지 전부 준비됐다.

그리고 지금 가장 큰 불확실성은 **규칙 자체가 아니라 사람이 그 규칙을 똑같이
적용할 수 있는가**다. 이것은 조사로 답할 수 없고 측정해야만 답이 나온다.

열려 있는 OQ 중 **1차 시험 30장을 막는 것은 없다.** 지침서 v1 이 미확정 항목을
"그리지 않는다 / Skip 한다" 로 처리하도록 쓰였기 때문이다 (접촉부 7종 = 그리지 않음,
엘보 = 검수 대상 분류). 이 사실을 `open_questions.csv` 의 새 열
`blocks_current_labeling` 에 전 항목 기록했다.

## 2. OQ-017 — 온도. **지금 결정하지 않는다**

측정 사실: `pilot/flir.py` 는 수정 없이 동작하고 IR1 100/100 성공 · IR2 0/100 ·
IR3 0/100. 온도를 가진 이미지는 2,512장(2.4%)뿐이며 정본 라벨 1,036장은 전부 IR1.

이 단계의 성과는 **"IR1 에서 온도 추출이 가능하다"를 확인한 것까지**다.
온도를 쓸지 말지는 모델 입력 설계 문제이고, 1차 목표는 객체 라벨링이다.

```
OQ-017  impact = future_model_input
        blocks_current_labeling = NO
        status = 조사완료·판정대기
```

## 3. OQ-010 — OSD. 마스킹 **보류**

`71.7%` 는 오염률이 아니다. OSD 픽셀이 한 번이라도 든 박스가 2,994개일 뿐,
실제 면적 손실은 5% 초과 49 · 10% 초과 8 · 25% 초과 0 · 최대 20.6% 다.
**큰 박스를 얇은 선이 스친 것이 대부분이다.**

따라서 `OSD 는 존재하지만 annotation 면적의 실질 손실은 작다` 로 기록하고
마스킹은 보류한다. 전처리를 지금 고정할 이유가 없다.

## 4. OQ-016 — 분할. cluster split **유지**

근접 미달 쌍 96,292 중 41,184(42.8%)이 split 을 가로지른다. 다만 이들은
**"같을 수도 있는 이미지"이지 확정 duplicate 가 아니다.** 확실한 클러스터 교차는 0 이다.

세션 단위 대안은 실측 후 기각했다 — 클러스터 교차 490건이라는 확실한 누수를
새로 만들고 P4·P7 의 val 이 0장이 된다. **불확실한 위험을 줄이려다 확실한 누수를
사는 교환이다.**

## 5. OQ-015 — 70/15/15 는 "정답"이 아니라 **기본 정책**

정본 라벨 1,036장이 train 723 / val 155 / test 158 (69.8/15.0/15.3%) 로 갈린다.
보고 문구를 이렇게 고정한다:

> 70/15/15 를 프로젝트 기본 분할 정책으로 적용했으며, 현재 데이터에서는
> 69.8/15.0/15.3 으로 구현되었다. **비율 자체의 근거는 별도로 확립하지 않았다.**

## 6. 작업시간 기록 — 왜 추가하는가

`agreement.py` 는 개수 일치 · mIoU · Kappa · Skip 을 잰다. 여기에 실무 지표
하나가 빠져 있다 — **30장에 실제로 얼마나 걸렸는가.**

이것을 모르면 400장 본 seed 와 그 이후 물량의 소요를 추정할 근거가 전혀 없다.
`annotator_*/time_log.csv` 에 구간별로 기록하고 `agreement.py` 가 함께 집계한다.

**속도 평가가 아니다.** 라벨러를 서로 비교하려는 것이 아니라 물량을 산정하려는
것이므로, 지침서에도 "빨리 하실 필요 없습니다 · 실제로 걸린 시간을 적으세요" 로 적었다.
오래 걸린 구간은 지침서가 고쳐야 할 지점을 가리킨다.

## 7. 순서

```
① 30장 시험 라벨링 (5인 독립)   ← 지금 여기. 사람 작업
② agreement + 작업시간 집계
③ OQ-015/016/017/010 병행 판정  (①과 독립적으로 진행 가능)
④ 규칙 보정 → 지침서 v2
⑤ 400장 seed 본 라벨링
```

③은 ①을 기다리지 않는다. ①은 ③을 기다리지 않는다. **둘은 서로 막지 않는다.**
