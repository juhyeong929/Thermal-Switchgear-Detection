# DEC-001 — 클래스 스키마를 가이드 v2 28개로 확정

## 날짜
2026-08-27

## 결정 내용
라벨링 클래스를 「수배전반 열화상 라벨링 가이드 v2」의 28개 체크포인트로 확정한다.
YOLO class_id 는 **가이드번호 − 1** 로 둔다. 정의는 `schemas/classes_v2.py` 한 곳에만 둔다.

## 문제
기존 작업(`pilot/classes.py`)은 2022.05.27 PDF 의 26개 스키마를 쓰고 있었다.
가이드 v2 는 명칭 3건 갱신, 보류→가공 4건 전환, 신규 항목 추가로 28개가 되었다.
두 스키마가 공존하면 라벨 파일의 class id 가 무엇을 뜻하는지 파일마다 달라진다.

## 검토한 선택지
1. **26개 유지, v2 는 문서로만 반영** — 라벨 변환은 없지만 가이드와 코드가 어긋난 채로 남는다.
   검증·인증 때 "가이드대로 라벨링했는가"에 답할 수 없다.
2. **v2 28개로 전환, class_id 를 0부터 재배열** — 깔끔하지만 가이드 종합표 번호와 어긋나
   대조할 때마다 변환표를 봐야 한다.
3. **v2 28개로 전환, class_id = 가이드번호 − 1** ← 선택

## 선택한 이유
검증·인증 과정에서 심사자가 보는 것은 가이드 종합표다. 라벨링 툴 화면의 class id 에
1을 더하면 곧바로 가이드 항목 번호가 되므로, 표를 사이에 두지 않고 대조할 수 있다.
0-index 변환은 기계적이라 오해의 여지가 없다.

## 근거
- 가이드 v2 `03 REFERENCE 가공 대상 종합` 표 28행 — 번호·명칭·가공여부의 출처
- 가이드 v2 hero `이번 개정에서 바뀐 내용` 10건 — alias 및 보류→가공 전환의 근거
- 가이드 v2 `02 PANELS` 반별 가공대상 — panel_candidates 의 출처
- 실측: 기존 라벨에 실제로 쓰인 구 클래스는 26개 중 9개뿐
  (`reports/data_audit/label_instance_inventory.csv`)

## 파생값 (가이드에 없으며, 파생임을 코드에 명시함)
- `class_id` = 가이드번호 − 1
- `priority` = 해당 클래스가 등장하는 반들의 가이드 우선순위 중 최솟값

## 영향
- 기존 4,177개 bbox 는 DEC-003 의 변환표로 전량 승계됨 (손실 0, 보류 0)
- `pilot/classes.py` 는 수정하지 않는다. 사전 실험 기록으로 그대로 둔다
- 신규 라벨링이 필요한 클래스: SA(#17). 케이블헤드(#14)는 구 `분기 접촉부`의 개명이나
  실제 라벨이 0건이라 사실상 신규다
