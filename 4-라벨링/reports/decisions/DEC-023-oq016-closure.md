# DEC-023 — OQ-016 종결: 현행 cluster split 유지 + 잔여 위험 문서화

## 날짜
2026-09-01

## 결정 내용

```
decision      = KEEP_CURRENT_CLUSTER_SPLIT
threshold     = 0.93 (변경 없음)
분할 단위      = cluster (변경 없음)
비율          = 70/15/15 (변경 없음 · 근거는 여전히 OQ-015)
residual_risk = 근접 후보군 내 동일 시야 잔여 가능성 — **known limitation 으로 관리**
```

잔여 위험을 **"해결해야 할 버그" 가 아니라 "알려진 한계" 로 관리한다.**
억지로 누수 위험을 0 으로 만들려고 분할 정책을 복잡하게 만드는 것보다,
현재 방식의 한계를 명시적으로 기록하는 것이 정직하다.

## 왜 닫는가 — 대안을 전부 실측하고 기각했다

| 대안 | 측정 결과 | 판단 |
|---|---|---|
| **현행 0.93 유지** | split 안정 · 같은 cluster 교차 0건 | **채택** |
| 임계값 하향 (0.925~0.910) | 동일 장면 포착 14~18% 뿐 · 과병합은 단조 증가 | 기각 |
| split 제약 S1 (사람 판정 22쌍) | 이동 0.13% · 분포 안정. 그러나 위험의 **0.27%** 만 덮음 | 안전하나 실익 없음 |
| split 제약 S2~S4 (자동) | 최대 덩어리 12~14% · **val 8.3~11.3% 붕괴** | 기각 |

**중간 지점이 없다.** 사람 판정을 8,200쌍으로 늘리는 것은 비현실적이고,
자동으로 범위를 넓히면 validation 분포가 무너진다.

## 확인된 것과 남은 것을 구분한다

**막고 있는 것** — 같은 cluster 가 train/val/test 로 갈라지는 사례는 **0건**이다.
확실하게 중복으로 판정한 데이터의 누수는 막고 있다.

**남은 것** — 클러스터링이 "근접하지만 확실하지 않은 동일 시야" 일부를
서로 다른 cluster 로 남길 수 있다. 리더 방식이 연쇄 병합을 막는 대가다.

## 잔여 위험의 성격 — 숫자를 오독하지 않게

**`20.0%` 는 전체 데이터의 누수율이 아니다.**

정확히는 **REV-005 의 층화 표본 101쌍을 기반으로 가중 추정한,
근접 유사 후보군 내 동일 시야 위험**이다.

| 오해 | 사실 |
|---|---|
| "데이터의 20% 가 누수됐다" | ✕ — 분모는 전체 데이터가 아니라 **split 을 가로지르는 근접 후보쌍 41,184** 이다 |
| "8,200장이 잘못됐다" | ✕ — 8,200은 **쌍**이지 이미지 수가 아니다 |
| "확정값이다" | ✕ — 101쌍 표본의 층화 가중 **추정치**다 |

## 보고 문구

> 근접 유사 후보쌍에 대한 표본 검증에서 일부 동일 시야가 확인되었으며, 층화 가중 추정
> 위험은 약 20%였다. 다만 이는 전체 데이터의 누수율이 아니라 cluster 외부의 근접
> 후보쌍을 대상으로 한 표본 기반 추정치이다. threshold 조정 및 split constraint
> 시뮬레이션에서는 안정적인 대안이 확인되지 않아 현행 cluster split 을 유지한다.

## 지표를 읽을 때 함께 적을 것

> 같은 클러스터가 두 split 에 걸친 사례는 0건이다. 다만 병합 기준을 아슬아슬하게 넘지
> 못한 근접 유사 쌍 중 약 20%(추정 8,200쌍)가 split 을 가로지른다.
> **val/test 지표는 이만큼 낙관적으로 나올 수 있다.**
