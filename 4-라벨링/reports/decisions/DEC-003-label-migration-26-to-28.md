# DEC-003 — 기존 26개 스키마 라벨을 v2 28개로 승계

## 날짜
2026-08-27

## 결정 내용
`pilot` 의 기존 라벨 중 **정본 3개 소스**만 v2 로 변환해 `data/labeling/reviewed` 에 둔다.
원본은 변환 전에 `data/backup` 으로 통째 복사한다. `pilot` 은 한 글자도 수정하지 않는다.

## 문제
`pilot` 에는 같은 이미지의 라벨이 여러 폴더에 흩어져 있었고, 어느 것이 최신 검수본인지
폴더명만으로는 알 수 없었다. 잘못 고르면 검수 이전 상태를 정본으로 삼게 된다.

## 검토한 선택지
1. 폴더명으로 추정해 `A3 검수완료` 를 정본으로 채택 — 이름에 의존하는 추정
2. **모든 소스를 읽어 파일 단위로 대조한 뒤 판정** ← 선택
3. 전부 병합 — 검수 이전 박스가 섞여 들어간다

## 선택한 이유
`scripts/audit_labels.py` 로 소스 간 공유 파일 수와 내용 일치 여부를 실측했다.
검수 단계가 진행될수록 박스가 늘어나는 계보가 수치로 확인되었고, 최종 두 소스가
완전히 동일하다는 것도 확인되어 추정 없이 정본을 고를 수 있었다.

## 근거 (실측 — `reports/data_audit/label_source_overlap.csv`)

P1 검수 계보. 파일 수는 786으로 같고 박스 수만 증가한다.

| 소스 | 박스 |
|---|---:|
| IR1_1반 (1차) | 750 |
| IR1_1반_A1검수 | 1,772 |
| IR1_1반_A2검수 | 2,586 |
| **A3 검수완료** | **3,574** |

동일성 확인:
- `A3 검수완료` vs `_p1only` — 공유 757파일, 상이 **0**. 같은 내용이다
- `_p3` vs `IR1_3반` — 공유 66파일, 상이 **0**

채택한 정본:

| 반 | 소스 | 파일 | 박스 |
|---|---|---:|---:|
| P1 | `A3 검수완료` | 786 | 3,574 |
| P3 | `_p3` | 66 | 227 |
| P4 | `_p4` | 184 | 376 |
| **합계** | | **1,036** | **4,177** |

제외한 것: `data/labels_pred`(모델 예측), `dataset/contact_stage*`(단일클래스 실험용
재인코딩), `data/labels_rgb*`(파일럿 100쌍 실험분). 사람이 그린 라벨이 아니거나
스키마가 다르다.

## 변환 결과 (실측 — `reports/data_audit/migration_verification.csv`)

```
변환 전 박스 4,177
변환 후 박스 4,177
보류(미변환)      0
손실              0
```

좌표는 건드리지 않았다. 바뀐 것은 class id 뿐이다.

변환 유형별 내역은 `schemas/class_migration_26_to_28.csv` 참조.
- `renamed` 3건 — 전력퓨즈 3분화, PT → 몰드타입 PT
- `status` 4건 — v1 보류 → v2 가공 전환 (접촉부 4종)
- `same` 18건
- `split` 1건 — 구 `분기 접촉부`. **실제 라벨 0건이라 이번 변환에서 발생하지 않았다**
- `new` 1건 — SA

## 영향
- 승계 후 라벨 실적이 있는 클래스는 28개 중 **9개**. 나머지 19개는 0건이다
- 반별로는 P1·P3·P4 에만 라벨이 있고 나머지 7개 반은 미착수다

  시드셋에 일부 포함시켜 함께 본다
