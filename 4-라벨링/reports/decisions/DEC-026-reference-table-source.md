# DEC-026 — 가공여부·제외 근거의 단일 출처를 `classes_v2.py` 로 확정하고 종합표를 재생성한다

```
상태        승인 대기 — 아래 승인란이 비어 있으면 이 문서는 아직 결정이 아니다
승인란      결정자: __________   날짜: __________
```

## 날짜
2026-09-02

## 문제 — 배포 가이드에서 근거 표가 사라졌다

이전 발주처 가이드(HTML)에는 `03 REFERENCE — 가공 대상 종합` 표가 있었다.

```
클래스 번호 1~28 · 한글명 · 가공여부(O/!/X) · 그렇게 정한 근거    한 장에 전부
```

`schemas/classes_v2.py` 와 `schemas/labeling_rules.py` 는 **그 표를 출처로 명시**하고 있다.

2026-09-02 배포판(PDF)에는 그 표가 없다. 20쪽 전부를 확인했다.

```
새 PDF 에 있는 것    반별 가공대상 목록 · 예시 사진 · 주의 문구 · CVAT 속성 설명
새 PDF 에 없는 것    클래스 번호 체계 · 가공여부 기호 · 근거 열
                    (p20 "5. 추가 내용" 은 제목만 있고 비어 있다)
```

그 결과 **현행 배포 가이드만으로는 다음을 설명할 수 없다.**

```
· class_id 가 왜 그 번호인가        (가이드번호 - 1 의 기계적 변환)
· 부스바 · 케이블 · ACB 접촉부가 왜 제외인가
```

그리고 이전 판 HTML 은 워크트리에서 삭제됐다. git 이력에만 남아 있다.

## 결정 내용

```
decision = SCHEMA_IS_SOURCE_OF_TRUTH_REGENERATE_REFERENCE_TABLE

     - 새 PDF 내용을 억지로 종합표 형태로 복원하지 않는다 (없는 것을 만들지 않는다)
2. 사람이 읽을 표는 스키마에서 재생성한다
     scripts/build_reference_table.py

3. 이전 판 HTML 은 1차 출처로서 git 이력에 보존한다
     paths.GUIDE_HTML 에 열람 방법을 주석으로 남긴다

```

## 왜 PDF 를 파싱해 표를 만들지 않는가

새 PDF 는 20쪽 / 이미지 191개 / **텍스트 총 약 1,400자**인 슬라이드 문서다.
클래스 번호도 가공여부 기호도 **원문에 존재하지 않는다.**
없는 것을 추론해 채우면 그것은 근거가 아니라 창작이다.

근거 문장 자체는 이미 코드로 옮겨져 있으므로, 표를 코드에서 되살리는 것이
원문에 없는 것을 만들지 않으면서 설명 가능성을 회복하는 유일한 방법이다.

## 표에서 제외와 폐지를 나눈다

```
O     가공   항상 라벨링
!     주의   식별 가능할 때만. 판별 불가면 미라벨/Ignore
X     제외   물체는 있지만 어떤 반에서도 그리지 않는다
폐지   폐지   가이드 개정으로 클래스 자체가 없어졌다 (DEC-025)
```

`X` 와 `폐지` 를 한 칸에 합치면 제외 3종의 근거를 설명할 수 없게 된다.
코드에서도 `EXCLUDED` 와 `RETIRED_CLASSES` 를 나눠 두고, 라벨 대상 판정에만
합집합 `NOT_LABELED` 를 쓴다.

```

· P4-MOF&PT반의 몰드타입 PT 는 새 판에도 이전 판에도 없고 저장소에만 있다 (NQ-14)
```
