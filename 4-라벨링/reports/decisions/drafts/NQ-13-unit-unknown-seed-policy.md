# [초안] NQ-13 — 단위 미확정 7종을 시드 수요에서 어떻게 다룰 것인가

```
상태        DRAFT — 승인 대기
승인란      결정자: __________   날짜: __________   DEC 번호: __________
대상        open_questions.csv  NQ-13  (부분 결정 — 단위 확정 자체는 계속 열림)
작성        2026-09-01 · 2차 실무 감사 후속
```

## 문제

`annotation_unit` 이 UNKNOWN 인 7종이 있다. 지침서는 이들을 "그리지 마세요" 로 처리한다.

```
LBS 1차측 접촉부 · LBS 2차측 접촉부 · 변압기 접촉부 · 분기 접촉부
VCB 접촉부 · 인입선로 접촉부 · CT 접촉부
```

그런데 `seed_select.panel_quota()` 는 이 7종을 **시드 수요에 포함**해 반 할당량을 계산한다.
"그리지 말라고 한 클래스 때문에 이미지를 배정하는 것이 맞는가" 가 이 문항이다.

## 실측 근거 — 두 가지를 분리해야 한다

### (1) 수요에서 빼면 얼마나 바뀌는가

`panel_quota()` 는 반별 수요의 **최댓값**을 쓴다. 한 장이 그 반의 후보를 동시에
커버하기 때문이다. 따라서 UNKNOWN 하나를 빼도 **다른 미관측 클래스가 같은 값을 요구하면
할당량은 그대로다.**

| 반 | 현행 | 7종 제외 시 | 차이 |
|---|---:|---:|---:|
| P5-PF&PT반 | 61 | 36 | **−25** |
| P7-VCB&CT반 | 61 | 36 | **−25** |
| 나머지 8개 반 | — | 전부 증가 | + |
| 합계 | 400 | 401 | |

**실제 이동은 50장(12.5%)이다.**
(2차 감사가 초판의 "183장(45.75%)" 을 정정한 항목이다 — `max` 산정을 오해했고,
SA 를 그리기 금지로 잘못 분류했다. SA 는 `WHOLE_OBJECT` 이며 A 가 실제로 3박스를 그렸다.)

### (2) "단위 미확정" 과 "데이터에 없음" 은 다르다

`reports/data_audit/class_evidence.csv` 실측 — 7종 중 **2종은 존재가 확인된다.**

| 클래스 | 정본 | 참고 | 존재 등급 | 배포 |
|---|---:|---:|---|---|
| VCB 접촉부 | 0 | **159** | CONFIRMED_PRESENT | X |
| 변압기 접촉부 | 3 | 0 | CONFIRMED_PRESENT | X |
| 나머지 5종 | 0 | 0 | NOT_YET_OBSERVED | X |

`vcb_contact` 의 근거 문구는 이전에 `"라벨 실적 0건"` 이었으나 **사실이 아니었다.**
참고 등급 P6 에 159박스가 실재하고, 프로젝트는 DEC-015 에서 참고 등급(P9 1,777박스)을
단위 판정 근거로 **이미 채택한 전례**가 있다.

DEC-015 와 같은 방법(접촉부 높이 / 본체 높이)으로 계산하면:

| 클래스 | 등급 | 박스 | 세로비 중앙 | DEC 판정 |
|---|---|---:|---:|---|
| 몰드변압기 접촉부 | canonical | 1,365 | 0.462 | `CONTACT_POINT` |
| 변류기 접촉부 | canonical | 219 | 0.379 | `CONTACT_POINT` |
| MCCB 접촉부 | reference | 1,777 | 0.922 | `TERMINAL_GROUP` |
| **VCB 접촉부** | reference | **159** | **0.246** | **미판정** |

## 결정 (안)

```
decision = KEEP_UNIT_UNKNOWN_IN_SEED_DEMAND
```

**세 가지를 함께 정한다.**

1. **시드 수요에서 유지한다.** 이미지 목록이 바뀌지 않아 시험셋 계보가 보존되고,
   P5·P7 의 61장은 낭비가 아니라 **그 반의 다른 배포 클래스**(소음기부착형 전력퓨즈 ·
   몰드타입 PT · CT)를 담는 장이다. 400장 라벨링 과정에서 실제 인스턴스가 관찰되면
   그것이 단위 판정의 근거가 된다 — NQ-13 의 원래 설계다.

2. **그러나 라벨링은 하지 않는다.** `annotation_unit` 이 미확정인 클래스를
   임의 단위로 그리게 하지 않는다. 시드 수요 포함과 배포 대상은 별개다.
   코드에서도 `labelable()`(수요)과 `deployable()`(배포)로 분리했다.

3. **존재 근거는 기록하되 단위를 자동 승격하지 않는다.**
   `vcb_contact` 의 근거 문구를 사실대로 고쳤으나 `annotation_unit` 은 UNKNOWN 을 유지한다.
   UNKNOWN → 확정은 **사람의 판정으로만** 이루어진다.

## 남는 것 — 이 초안이 닫지 않는 것

```
· 7종의 annotation unit 확정          여전히 열림 (NQ-13 본체)
· vcb_contact 단위 판정               근거는 확보됐다. 판정은 사람이 한다
  -> 별도 판정 문서를 쓸 것. 데이터가 가리키는 방향은 CONTACT_POINT 이지만
     감사·도구가 대신 정하지 않는다
· C-3(클래스당 30~50)                7종은 이번 시드에서 인스턴스 0 이 확정적이다.
  보고에 그대로 적는다
```

## 영향

**이미 코드에 반영된 것**

| 무엇 | 어디 |
|---|---|
| 수요 유지 (quota 무변경, 400장 동일) | `seed_select.panel_quota()` — 변경 없음 |
| 수요 ↔ 배포 분리 | `classes_v2.labelable()` / `deployable()` |
| `vcb_contact` 근거 문구 정정 | `classes_v2.ANNOTATION_UNIT_BASIS` |
| 존재 근거 4소스 집계 + "0건이라 적었는데 실재" 자동 경고 | `scripts/build_class_evidence.py` |

**아직 하지 않은 것**

- `open_questions.csv` NQ-13 상태 갱신 — **승인 후 사람이 한다**
  (닫는 것이 아니라 "시드 정책 부분 결정 · 단위 확정은 계속 열림" 으로)

## 되돌리는 법

수요에서 빼려면 `panel_quota()` 의 필터에 `not v2.unit_confirmed(...)` 를 추가한다.
그 경우 **10개 반 전부 quota 가 바뀌고 이미지 목록이 대폭 변경**되므로,
`status_check` [5-1] 이 `IMAGE_SET_CHANGED` 로 잡고 시험셋 A군 18장의 잔류 여부를 확인한다.
