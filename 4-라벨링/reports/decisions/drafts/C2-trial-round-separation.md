## 문제

C-2 는 원래 "5인 시험 후 단일 Kappa" 로 설계됐고, `deploy_checklist_D_E.md` 는
그래서 **"지침서 v1 을 고치지 않는다 — 고치면 5인 비교가 무의미해진다"** 를 못박았다.

그런데 3인 시점에서 **운영조건 자체를 바꿔야 한다는 결론**이 나왔다(NQ-15).
반 정보를 공개하면 D·E 는 A·B·C 와 다른 조건에서 작업하게 된다.

두 가지 중 하나를 골라야 한다.

| | 내용 | 대가 |
|---|---|---|
| **(a)** | **3인에서 v1 을 끊고 v2 로 전환** | 5인 단일 조건 데이터 포기 |
| (b) | D·E 를 v1 으로 마저 받고 그 다음 v2 | 이미 3/3 재현된 NQ-15 를 5/5 로 확인할 뿐 |

## 결정 (안)

```
decision = SPLIT_TRIAL_ROUNDS_BY_GUIDE_VERSION      # 선택지 (a)
```

**근거.** NQ-15 는 3/3 으로 이미 충분히 재현됐다. D·E 를 같은 조건으로 태우면
**새 정보 없이 2명분을 소모**한다. 그 2명은 v2 검증에 쓰는 편이 낫고,
그러면 `A/B/C(v1) → 규칙 개선 → D/E(v2)` 라는 **전후 비교 실험**이 된다.
이것은 5인 평균보다 연구적으로 더 강한 설계다.

## 회차 정의

등록부: `data/labeling/draft/trial/trial_versions.csv` (단일 출처)

| round | guide_version | 라벨러 | 반 정보 | 상태 | 목적 |
|---:|---|---|---|---|---|
| 1 | v1 | A · B · C | 비공개 | CLOSED | v1 규칙의 초기 재현성 검증 |
| 2 | v2 | D · E | **공개** | PENDING | v2 개선 규칙의 재현성 검증 |

```
· v1 결과(pooled Kappa 0.902)는 **기존 값 그대로 영구 보존**한다
· v2 결과를 v1 CSV 위에 덮어쓰지 않는다
· 두 회차의 Kappa 를 하나로 평균하지 않는다 — 운영조건이 다르므로
  무엇을 측정한 값인지 말할 수 없게 된다
```

## C-2 지표 정의

### 산출하는 것

| 지표 | 정의 | 무엇을 말하는가 |
|---|---|---|
| pooled Kappa | 쌍별 Cohen's κ 의 산술평균 | 클래스 정의가 통했는가 (**참고값**) |
| panel-stratified Kappa | 반별 Cohen's κ | 어느 반에서 통했고 어디서 무너지는가 |
| count agreement | (이미지 × 클래스) 조합의 개수 일치율 | **무엇을 그릴지가 통했는가** |
| mIoU | 짝지어진 박스의 IoU 평균 | 경계 규칙이 통했는가 |
| Skip | 라벨러별 이미지 Skip 수 (반별 분해) | 어느 규칙에서 막히는가 |
| **paired coverage** | `2 × 짝지어진 박스 / (A 박스 + B 박스)` | **Kappa 가 얼마나 좁은 기반 위의 값인가** |

### pooled Kappa 를 단독 인증 근거로 쓰지 않는다

**이유 — 실측.** v1 3인 결과에서 반별로 분해하면 다음과 같다.

| 반 | 배포 클래스 | 짝지어진 박스 | Kappa | count agreement |
|---|---:|---:|---:|---:|
| P9 | 2종 | 68~82 | **1.000** | 71~88% |
| P1 | 4종 | 5~11 | 1.000 | 40~63% |
| P6 | 3종 | 4~6 | 0.000~1.000 | 0~100% |
| P4 | 5종 | 3~7 | **0.000~0.417** | 0~20% |
| P3 | 3종 | 0~3 | — | — |

**짝지어진 박스 90개 중 68개(76%)가 P9 이고, P9 은 배포 클래스가 2종뿐이다.**
즉 pooled Kappa 0.902 는 사실상 **"P9 에서 MCCB 와 MCCB 접촉부를 구분할 수 있는가"** 를
측정한 값이다. 후보가 많은 P4 에서는 0.0~0.42 로 무너진다.

### 주의 문구를 자동 병기한다

다음 조건에 걸리는 반에는 `interpretation_warning` 이 자동으로 붙는다
(`scripts/agreement.py`). **값을 깎거나 버리지 않는다 — 읽는 법을 함께 적는다.**

```
배포 클래스 2종 이하        "클래스 선택지가 좁아 Kappa 가 높게 나온다"
비교 5장 미만               "표본 부족"
paired coverage 70% 미만    "짝이 안 지어진 박스가 많다"
```

그리고 `certification_evidence.py` 가 C-2 detail 에
**"해석 주의 반이 짝지어진 박스의 N%"** 를 자동으로 적는다.

### 보고 문구 (그대로 쓸 것)

> **C-2 — v1 3인 시험: PASS**
> pooled Kappa 0.902 (3쌍 평균 · A·B·C 독립 라벨링 · 반 정보 비공개)
> 목적: v1 규칙의 초기 재현성 검증
> 제한: 3인 결과이며 **5인 최종 인증값이 아니다.** Kappa 는 IoU≥0.5 로 짝지어진
> 박스에서만 산출되며(기반 74%), 짝지어진 박스의 76%가 배포 클래스 2종인 P9 에서 나왔다.
> **pooled 값을 단독 인증 근거로 해석하지 않는다.** 반별 값을 함께 읽는다.
> D·E 는 v2 개선 검증군으로 별도 기록한다.

## 이 결정이 만드는 새 위험

v1 과 v2 의 차이가 **지침서 개선 때문인지 반 공개 때문인지 분리되지 않는다.**
두 변경이 동시에 들어가기 때문이다.

완화 — v2 회수 시 다음을 함께 본다.

```
· 후보 밖 클래스 박스 수 (v1: A 3 · B 23 · C 3)  -> 반 공개 효과의 직접 지표
· 반별 count agreement 변화                      -> 지침서 개선 효과
```

그리고 **NQ-12 의 0.003 을 v2 지침서에 넣지 않는다.** 넣으면 세 번째 변경이 섞여
전후 비교가 더 흐려진다. (`status_check` [5-2] 가 유출을 자동 검사한다.)
