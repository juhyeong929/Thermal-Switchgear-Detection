## 왜 이 한 종만 지금 정할 수 있는가

NQ-13 은 7종을 "라벨 실적 0건" 이라는 **공통 전제**로 묶었다. 그 전제가 틀렸다.

```
schemas/classes_v2.py  ANNOTATION_UNIT_BASIS["vcb_contact"]
  (이전) "라벨 실적 0건 (NQ-13)"        <- 사실이 아니었다
  (현재) "참고 P6 159박스 존재 · 단위 미판정"
```

`data/backup/P6_6ban` 에 구 class_id 17(VCB 접촉부) **159박스 / 111장**이 실재한다.
그리고 프로젝트는 **DEC-015 에서 참고 등급을 단위 판정 근거로 이미 채택**했다
(P9 참고 1,777박스로 MCCB 접촉부를 `TERMINAL_GROUP` 으로 확정).

즉 **같은 증거 등급 · 같은 방법이 이미 전례로 있다.**
나머지 6종은 정본·참고 어디에도 박스가 없으므로 이 경로를 쓸 수 없다.

## 1부 — P6 기존 annotation 은 어떻게 되어 있었는가 (관찰)

> **이것은 관찰이지 결정이 아니다.** 참고 등급은 검수 이력이 없어 정본 승격이
> 보류된 라벨이다(DEC-011 · KL-5). 아래 수치는 "과거에 누군가 이렇게 그렸다" 이지
> "이렇게 그리는 것이 옳다" 가 아니다.

### 크기 — DEC-015 와 같은 방법(접촉부 높이 / 본체 높이)

| 클래스 | 등급 | 박스 | 세로비 중앙 | p25~p75 | 확정 단위 |
|---|---|---:|---:|---|---|
| 몰드변압기 접촉부 | canonical | 1,365 | 0.462 | — | `CONTACT_POINT` |
| 변류기 접촉부 | canonical | 219 | 0.379 | — | `CONTACT_POINT` |
| MCCB 접촉부 | reference | 1,777 | 0.922 | 0.87~0.97 | `TERMINAL_GROUP` |
| **VCB 접촉부** | reference | **159** | **0.246** | **0.18~0.31** | **미판정** |

`TERMINAL_GROUP` 은 "기기 세로 전체를 훑는 스트립"(0.922)이었다.
VCB 접촉부의 0.246 은 그것과 전혀 다르고, `CONTACT_POINT` 로 판정된 두 클래스보다도 작다.

### 개수 — 장당 1개가 지배적이다

```
장당 접촉부 개수   1개 74장 · 2개 31장 · 3개 3장 · 4개 1장 · 5개 2장   (중앙 1)
```

**여기가 해석이 갈리는 지점이다.** `CONTACT_POINT` 라면 3상 설비에서 장당 3개 안팎이
나오는 것이 자연스럽다(몰드변압기 접촉부는 장당 중앙 3개다).
장당 1개가 74/111 이라는 것은 다음 중 하나를 뜻한다.

| 가능성 | 함의 |
|---|---|
| (a) 클로즈업이 많아 한 장에 접속점이 하나만 보였다 | `CONTACT_POINT` 와 모순 없음 |
| (b) 여러 접속점을 하나로 묶어 그렸다 | `TERMINAL_GROUP` 에 가까움 |
| (c) 보이는 것만 골라 그렸다 (미작업 의심분) | 참고 등급 보류 사유 그 자체 |

**좌표만으로는 (a)(b)(c) 를 가를 수 없다.** DEC-016 이 CONTACT_POINT 준수 여부에 대해
같은 한계를 기록했다 — "좌표만으로는 하나의 물리적 접속점마다 박스 하나인가를
확정할 수 없다".

### 케이블헤드와의 관계 — 지침서 §6 예시와 어긋난다

지침서 v1 §6 은 "정상인 겹침" 의 대표 예로 이렇게 적었다.

> "케이블헤드 박스 안에 VCB 접촉부 박스가 들어갑니다."

실측은 다르다.

```
접촉부 보유 이미지 111장 중 케이블헤드가 함께 있는 이미지   44장 (40%)
그 44장의 접촉부 69박스 중 케이블헤드 안에 90% 이상 포함    6박스 (9%)
케이블헤드 1개당 접촉부 개수 중앙                          0.50
```

**91% 는 케이블헤드 밖에 있다.** 지침서의 유일한 겹침 예시가 프로젝트가 보유한
유일한 실증 데이터와 반대 방향이다.

## 2부 — v2 에서 새로 어떻게 그릴 것인가 (결정 대상)

> **1부와 분리해서 정한다.** 과거 라벨을 따라 그리는 것이 목표가 아니다.
> 과거 라벨은 참고 등급이고, 우리는 이번에 **새 기준**을 세우는 중이다.

### 선택지

| | 결정 | 근거 | 위험 |
|---|---|---|---|
| **(1)** | **`CONTACT_POINT` 로 확정** | 세로비 0.246 이 CONTACT_POINT 두 클래스(0.462·0.379)보다 작다. DEC-015 의 판정 논리를 그대로 적용한 결과 | 장당 1개 지배가 설명되지 않는다. 참고 라벨이 (b)나 (c)였다면 근거가 흔들린다 |
| (2) | `TERMINAL_GROUP` 으로 확정 | 장당 1개가 지배적 | 세로비 0.246 이 TERMINAL_GROUP(0.922)과 정면으로 어긋난다 |
| **(3)** | **UNKNOWN 유지 + v2 관찰 항목으로 지정** | 좌표만으로 (a)(b)(c) 를 가를 수 없다는 것이 DEC-016 이 이미 인정한 한계다 | 7종 중 1종이 계속 배포에서 빠진다. P6·P7 의 배포 클래스가 각각 3종·1종에 머문다 |
| (4) | 육안 확인 후 확정 | 표본 15~20장을 열어 (a)(b)(c) 를 가른다. 반나절 | 없음 — 다만 사람 시간이 든다 |

### 권고 (안)

```
decision = RESOLVE_BY_VISUAL_SAMPLE_THEN_CONFIRM      # 선택지 (4) -> (1) 또는 (2)
```

**이유.** 크기 근거는 `CONTACT_POINT` 를 강하게 가리키지만 **개수 근거가 반대 방향**이다.
두 근거가 어긋날 때 좌표만으로 결정하면, 그것은 DEC-016 이 "NOT_AUDITABLE" 로
분류한 판단을 자동화하는 것이 된다.

**필요한 것은 새 데이터가 아니라 15~20장을 여는 일이다.**

```
확인 절차
  1. 접촉부가 2개 이상인 장(37장) 중 5장 · 1개인 장(74장) 중 10장을 뽑는다
  2. 각 장에서 물리적 접속점이 몇 개 보이는지 센다
  3. 라벨 박스 1개가 접속점 1개를 감싸는가, 여러 개를 묶었는가를 본다
  4. (a) 이면 CONTACT_POINT · (b) 이면 TERMINAL_GROUP · (c) 면 근거로 쓰지 않는다
```

**(3) 을 권하지 않는 이유** — P7-VCB&CT반은 배포 클래스가 **CT 1종뿐**이다.
VCB 접촉부가 풀리면 2종이 되어 그 반의 시험이 의미를 갖는다.
반나절 작업으로 반 하나의 측정 가능성이 달라진다.

### 확정 시 지침서에 들어갈 문구 (초안)

`CONTACT_POINT` 로 확정될 경우:

```
VCB 접촉부
포함  볼트로 조여진 접속 지점 하나하나. 접속점마다 박스 하나.
제외  케이블헤드 본체(리브 적층부)와 거기서 이어지는 도체.
      케이블헤드는 별도 클래스로 따로 그립니다.
애매  접속점이 겹쳐 몇 개인지 셀 수 없으면 Skip 합니다.
```

**그리고 지침서 §6 의 겹침 예시를 고쳐야 한다.** 현재 "케이블헤드 안에 VCB 접촉부가
들어간다" 는 실측 9% 와 어긋난다. 예시를 실제 데이터에 맞게 바꾸거나 다른 클래스 쌍으로
교체한다.
