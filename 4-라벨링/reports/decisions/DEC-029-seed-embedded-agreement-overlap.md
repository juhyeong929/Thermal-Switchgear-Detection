# DEC-029 — 400장 본작업 안에 중복 배정 50장을 심어 v2 조건 C-2 를 측정한다

```
상태        승인 대기 — 아래 승인란이 비어 있으면 이 문서는 아직 결정이 아니다
승인란      결정자: __________   날짜: __________
```

## 날짜
2026-09-03

## 문제

DEC-028 로 2차 시험 회차를 취소하면서 **v2 운영조건(반 정보 공개 · 반별 CVAT task)의
C-2 를 낼 경로가 없어졌다.** 그대로 두면 C-2 는 v1 조건 4명 값에 영구히 머물고
BLK-3 는 닫히지 않는다.

## 결정 내용

```
decision = EMBED_AGREEMENT_OVERLAP_IN_SEED

400장 본작업 안에서 50장을 두 사람에게 중복 배정한다.
별도 회차를 되살리지 않는다.
```

**같은 사람이 두 번 그리는 것이 아니다.** 두 사람이 **서로 모르게 처음부터** 각자
그린다. 한쪽 결과를 보여 주고 고치게 하면 그것은 재현성이 아니라 수정률이 된다.

```
seed_A ─┐
        ├─ 동일 원본 50장 · 독립 라벨링
seed_B ─┘
```

## 왜 50장이고, 왜 그 배분인가

```
P1  5   P2  5   P3  4   P4  5   P5  5
P6  5   P7  5   P8  5   P9  6   P10 5      = 50
```

**단순 비례로 뽑지 않는다.** 모집단이 이렇게 치우쳐 있다.

| 반 | 시드 | 비례 배분이면 | 실제 배분 |
|---|---:|---:|---:|
| P2 · P5 · P6 · P7 | 61 | 8 | 5 |
| P3 | 15 | **2** | **4** |
| P9 | 21 | **3** | **6** |

비례로 뽑으면 P3 는 2장, P9 는 3장이 되어 **agreement 계산에 들어가지 못한다.**
1차 시험에서 P3 는 비교 가능한 장이 0~1장이라 Kappa 가 아예 나오지 않았다.
그래서 **반별 최소 표본 + P9 보강**으로 간다.

P9 를 더 주는 이유가 하나 더 있다. 1차 시험에서 짝지어진 박스 90개 중 68개(76%)가
P9 였고, 그래서 pooled Kappa 0.902 는 사실상 "P9 에서 MCCB 와 MCCB 접촉부를 구분할 수
있는가" 를 잰 값이었다. P9 의 표본이 적으면 이번에도 같은 편향이 생긴다.

## 어떻게 뽑았는가 — 무작위가 아니다

`seed_set_export.pick_overlap()` 이 반별로 **세션 순 정렬 후 균등 간격**으로 집는다.

```
같은 세션에서만 뽑히면   같은 장면을 두 번 보는 셈이라 일치도가 부풀려진다
균등 간격으로 집으면     세션을 가로지른다. 실제 5장에 세션 4~5개가 들어갔다
```

같은 입력이면 언제 돌려도 같은 50장이 나온다. 대상은
`data/labeling/seed/deploy/agreement_subset.csv` 에 고정돼 있고,
`deploy_manifest_seed.csv` 지문(70개 항목)에 포함된다.

## 별도 작업으로 다루지 않는다

50장은 **400장 배포 안에 들어 있고 manifest 로만 구분된다.** 따로 빼서 보내지 않는다.
그래야 라벨러가 "이건 시험이구나" 하고 다르게 작업하지 않는다.

`seed/deploy/manifest.csv` 에 다음 열이 있다.

```
agreement_subset   50 (중복 배정 대상이면) / 0
overlap            true / false
annotator_pair     seed_A/seed_B          <- 배포 시 실제 이름으로 바꾼다
```

## 어떻게 기록하고 읽는가

**v1 값을 덮어쓰지 않는다.** `trial_versions.csv` 에 나란히 둔다.

| round | guide | 조건 | C-2 |
|---:|---|---|---|
| 1 | v1 | 반 비공개 · 3인 | **0.902 baseline** — 그대로 보존 |
| 3 | v1+vcb | 반 비공개 · 1인 | 같은 조건 4번째 사람 |
| 4 | **v2.0** | **반 공개 · 반별 task · 본작업 내 50장** | 이번 측정 |

**이 값은 "v2 검증 완료" 가 아니다.** 정확한 표현은
**"본작업 중 확보한 v2 agreement evidence"** 다. 별도 설계된 시험이 아니라
본작업에서 부수적으로 얻은 근거이므로, 시험 회차와 같은 지위를 주지 않는다.

**pooled 값을 단독으로 읽지 않는다.** 반별 값과 paired coverage 를 함께 본다
(C-2 회차 분리 초안의 지표 정의 그대로).

```
P3 · P9   배포 클래스가 2~3종이라 선택지가 좁아 Kappa 가 높게 나온다
P3 · P4   반-클래스 정책이 아직 잠정이다 (NQ-14 · PANEL_CLASSES_PROVISIONAL)
```

이 반들의 값을 전체 대표값으로 확대 해석하지 않는다. `agreement.py` 가
`interpretation_warning` 을 자동으로 붙인다.

## 배포 전에 끝내야 하는 이유

50장을 **배포한 뒤에 지정하면 안 된다.** 나중에 고르면 "결과를 보고 고른 것 아닌가" 를
반박할 수 없다. 그래서 배포 전에 확정하고 입력판을 잠갔다.

```
python scripts/lock_deploy_manifest.py --target seed --verify
  round 4 · guide v2.0 — 70개 항목 전부 일치
```

`trial_versions.csv` round 4 의 `status` 가 `PENDING` 인 동안에만 다시 잠글 수 있다.
배포를 시작하면 `IN_PROGRESS` 로 바꾼다 — 그 뒤에는 `--force` 로도 50장을 바꿀 수 없다.

## 이 결정이 닫지 못하는 것

```
BLK-3 를 완전히 닫지는 못한다. 이것은 2인 · 50장 근거이고,
인증이 상정한 5인 독립 시험이 아니다. 그 사실을 지표 옆에 병기한다.
```
