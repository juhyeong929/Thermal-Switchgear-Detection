# 바운딩박스 경계 규격서 (OQ-006)

> 2026-08-27 · 근거: 가이드 v2 원문·예시 이미지 + 정본 4,177박스 + 참고 3,339박스 실측
> 상위 결정: `DEC-004`(제외·Ignore) · `DEC-007`(잘림) · `DEC-012`·`DEC-013`(케이블헤드) ·
> `DEC-014`(접촉부 클래스별 분리) · `DEC-015`(annotation unit 체계)
>
> **[배포 상태] 5개 항목 모두 배포 가능. 단 클래스별로 갈린다.**
> `접촉부` 는 상위 개념일 뿐이며 **클래스마다 annotation unit 이 다르다.**
> 단위가 확정된 18/25 클래스만 배포하고, 나머지 7종은 보류한다
> (`schemas/classes_v2.py` 의 `ANNOTATION_UNIT` · `unit_confirmed()`).
> 케이블헤드의 엘보·베이스 취부는 전문가 확인 대기이며 라벨러는 Skip 한다.

## 표기

```
INCLUDE     항상 포함
EXCLUDE     항상 제외
CONDITIONAL 조건부 — 조건을 명시한 경우만
UNKNOWN     근거 없음. 확정하지 않는다
PENDING_EXPERT_REVIEW  전문가 확인 대기. 라벨러는 Skip 처리
```

# 1. 케이블헤드 (#14)

```
semantic mapping        = CONFIRMED        (구 분기 접촉부 = v2 케이블헤드, DEC-013)
boundary policy         = MOSTLY CONFIRMED
expert-dependent items  = PENDING          (엘보, 베이스·취부 구조)

## 원칙
케이블 종단접속재 조립체를 하나의 객체로 본다.

  두 예시 모두 CVAT 라벨명이 `분기 접촉부` 이며, 박스는
  **상단 금속 단자에서 시작해 리브 적층부 아래에서 끝난다. 그 아래 케이블은 박스 밖이다.**

# 2. 접촉부 계열

```
boundary policy = CLASS-DEPENDENT — 공통 규칙을 배포하지 않는다
annotation unit = 클래스별로 별도 정의 (schemas/classes_v2.py ANNOTATION_UNIT)

## 원칙 — 클래스마다 단위가 다르다

# 3. 잘림 (truncated)

```
boundary policy = CONFIRMED — 기존 정책과 실측이 일치한다
```

## 원칙 (DEC-007, 변경 없음)
```
분모 = 그 부품을 잘리지 않게 촬영했을 때 추정되는 전체 면적
노출 비율 <  30%  -> 박스 생략 (Ignore)
노출 비율 >= 30%  -> 보이는 영역만 박스, truncated = true
```

## 실제 데이터 사례

| 집합 | 박스 | 1변 접촉 | **2변 이상** |
|---|---:|---:|---:|
| 정본 P1/P3/P4 | 4,177 | 1,190 (28.5%) | **17** |
| 참고 P6 | 546 | 138 (25.3%) | **1** |
| 참고 P9 | 2,793 | 750 (26.9%) | **1** |
| 합계 | 7,516 | 2,078 (27.6%) | **19 (0.25%)** |

## 해석
1변 접촉은 약 28%로 흔하다 — 잘렸어도 형태를 알아볼 수 있어 박스를 쳤다는 뜻이다.
2변 이상 접촉은 **0.25%** 로 사실상 없다. 심하게 잘린 대상은 애초에 박스를 안 쳤다.

**기존 DEC-007 정책과 모순되지 않는다.** `labeling_rules.py` 를 수정하지 않았다.

## 라벨러 문구

```
[잘림]
포함  한쪽 변만 잘렸고 무엇인지 알아볼 수 있으면 보이는 부분만 박스 치고 truncated 표시.
제외  원래 크기의 30% 미만만 보이면 박스를 치지 않는다.
애매  두 변 이상 잘려 형태를 못 알아보겠으면 Skip 하여 검수로 넘긴다.
```

# 4. 작은 객체

```
boundary policy = CANDIDATE THRESHOLD — 공식 임계값으로 확정하지 않는다
```

## 원칙 (DEC-004, 변경 없음)
너무 작아서 **부품 종류를 식별할 수 없으면** 박스를 생략한다.
식별 가능성이 기준이지 픽셀 수가 기준이 아니다.

## 실제 데이터 사례

| 클래스 | 등급 | 초소형(면적<0.0015) | 비율 |
|---|---|---:|---:|
| 몰드변압기 접촉부 | canonical | 39 / 1,365 | 2.9% |
| 변류기 접촉부 | canonical | 4 / 219 | 1.8% |
| MCCB 접촉부 | reference | 21 / 1,778 | 1.2% |

면적 5퍼센타일 — 정본 **0.0027**, 참고 **0.0034**.

## 현재 상태
```
candidate_threshold = 정규화 면적 0.003  (320x240 에서 약 15x15 px)
```

세 클래스가 비슷한 값으로 모이지만 **셋 다 접촉부 계열**이다.
접촉부가 아닌 클래스의 작은 객체 사례가 아직 없다.
**공식 임계값으로 만들지 않는다.** 다른 클래스 사례를 더 모은 뒤 다시 판단한다 (NQ-12).

## 라벨러 문구

```
[작은 객체]
포함  작아도 무슨 부품인지 알아볼 수 있으면 박스를 친다.
제외  종류를 알아볼 수 없을 만큼 작으면 박스를 치지 않는다.
애매  알아볼 듯 말 듯 하면 Skip 하여 검수로 넘긴다. 픽셀 수로 재지 않는다.
```

# 5. 중첩 · 겹침

```
boundary policy = CONFIRMED
```

## 원칙

**같은 인스턴스를 뜻하는 박스를 두 개 만들지 않는다.**
`[케이블헤드 전체]` 와 `[케이블헤드 상단부]` 를 동시에 그리지 않는다.

**서로 다른 물리적 객체라면 각각 박스를 만든다.**
겹쳐 보인다는 이유로 하나의 그룹 박스로 묶지 않는다 (DEC-004, `ALLOW_GROUP_BOX = False`).

**다른 클래스끼리의 겹침은 정상이다.**
가이드 v2 `VCB 반 전경` 에서 케이블헤드(적) 박스 안에 VCB 접촉부(주황) 박스가 들어간다.

## 실제 데이터 사례

| 집합 | 같은 클래스 IoU ≥ 0.6 중첩 |
|---|---:|
| 참고 P6 + P9 | **1 / 3,339** |
| 참고 P6 포함관계 박스 | 4 / 387 (2장) |

규칙이 대체로 지켜지고 있으며, 위반은 `case_04` · `case_05` 에 예시로 남겼다.

## 오답 bbox와 이유

| 오답 | 왜 틀렸는가 |
|---|---|
| 큰 박스 + 그 안의 같은 클래스 작은 박스 | 인스턴스가 두 개로 세어진다 |
| 나란한 세 조를 한 박스로 묶기 | 그룹 박스는 허용하지 않는다. 개별 경계를 못 나누면 Ignore |
| 다른 클래스와 겹친다고 하나를 지움 | 다른 클래스끼리의 겹침은 정상이다 |

## 라벨러 문구

```
[중첩·겹침]
포함  서로 다른 물체면 겹쳐 보여도 각각 박스를 친다. 다른 클래스끼리 겹치는 것은 정상이다.
제외  같은 물체에 박스를 두 개 그리지 않는다. 여러 개를 한 박스로 묶지도 않는다.
애매  같은 물체가 겹쳐 개별 경계를 못 나누겠으면 Skip 하여 검수로 넘긴다.
```
