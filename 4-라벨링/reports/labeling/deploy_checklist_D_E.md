## 배포 전 — 자동과 사람을 나눈다

> **2026-09-02 개정.** 이전 판은 자동 검사와 사람 확인이 한 목록에 섞여 있었다.
> 자동으로 이미 PASS 인 항목까지 손으로 체크하게 되어, 정작 **사람만 할 수 있는

### [사람 확인] — 파일시스템에서 알 수 없는 것

**자동 검사가 닿지 않는 곳은 화면이다.** 아래는 CVAT 를 실제로 띄워야 확인된다.

```
[ ] CVAT 프로젝트·task 를 실제로 만들었는가
       task 이름 = generated/cvat_tasks.csv 의 cvat_task_name 그대로
       예) "P6 · P6-VCB반"
[ ] 각 task 의 Raw 탭에 **그 반의** 라벨 정의를 넣었는가
       generated/cvat_labels/<PID>.json — 반마다 다르다. 한 파일을 돌려쓰지 않는다
[ ] 라벨러 화면에 **반 이름이 실제로 보이는가**  (A-1 · NQ-15 의 핵심)
[ ] 라벨 목록이 화면에 그 반 것만 뜨는가
       파일이 맞아도 프로젝트에 잘못 붙이면 다른 반 목록이 뜬다
[ ] 박스 속성 칸(truncated / ignore / 촬영유형)이 화면에 보이는가
[ ] escalation 연락처가 라벨러가 볼 수 있는 곳에 실제로 표시되는가
       파일에 적혀 있는 것과 화면에 보이는 것은 다르다
[ ] D·E 에게 자기 반 이름과 배포 클래스 목록을 전달했는가
       generated/panel_class_table.md 의 해당 행을 그대로 보낸다
[ ] **CVAT 화면에 기존 라벨이 미리 들어가 있지 않은가**   <- 아래 주의
```

> **pre-annotation 확인이 자동과 사람으로 나뉘는 이유**
>
> `status_check [1]` 은 **"D·E 폴더에 라벨 파일이 없다"** 까지만 보장한다.
> 그것은 회수 경로가 깨끗하다는 뜻이지, **CVAT 화면에 라벨이 주입되지 않았다는
> 뜻이 아니다.** pre-annotation 은 CVAT 서버 쪽에 들어가므로 파일시스템에
> 흔적이 남지 않는다.
>
> **task 를 열어 첫 장에 박스가 하나도 없는 것을 눈으로 확인한다.**
> 미리 들어가 있으면 라벨러는 그것을 고치는 작업을 하게 되고, 그때 나온 값은
> 재현성 측정이 아니라 수정률 측정이 된다.

## A·B·C 결과에서 나온 것 — D·E 에게 특별히 말해 둘 것

**`scope=object` 를 쓸 수 있다는 것을 다시 알려 준다.**
A · B · C **세 명 모두** `scope=object` 사용 0회였다. Skip 26건이 전부 `scope=image` 다.
3/3 이면 개인 성향이 아니라 문구 문제다. 한 장에 박스 6개가 있고 그중 하나만
애매해도 통째로 빠지면 비교할 표본이 사라진다.

> "한 장에서 **일부만** 애매하면 나머지는 그리고, 그 하나만 `scope=object` 로 적어 주세요.
> 장 전체를 못 하겠을 때만 `scope=image` 입니다."

이것은 규칙 변경이 아니라 **v1 에 이미 있는 항목을 다시 안내하는 것**이다.
