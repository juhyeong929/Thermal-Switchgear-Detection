# 열화상 부품 라벨링 지침서 v1

> 수배전반 열화상 · 객체 탐지용 바운딩박스
> 2026-08-27 · 근거: `bounding_box_boundary_spec.md` · `DEC-004/007/012~015`
>
> **이 버전은 1차 시험 라벨링(30장)용이다.** 여기서 나온 불일치를 반영해 v2 를 만든다.
> **18개 라벨 대상 중 4개 핵심 클래스 집중 시험**이다 (아래 '이번 시험의 범위' 참조).

## 이번 시험의 범위 — 반드시 읽고 시작하세요

```
지침서가 규정하는 라벨 대상   18종
이번 30장이 집중 검증하는 것    4종
이번 30장에서 검증되지 않는 것  14종 (WHOLE_OBJECT 계열)
```

**18개 라벨 대상 중 4개 핵심 클래스 집중 시험**입니다.

| | 클래스 | 왜 |
|---|---|---|
| **집중 검증 4종** | 몰드변압기 접촉부 · 변류기 접촉부 · MCCB 접촉부 · 케이블헤드 | 세는 단위와 경계가 갈렸던 클래스. 지금까지 확인된 **가장 위험한 지점** |
| **이번 미검증 14종** | LBS · LA · 전력퓨즈 3종 · 변압기 · 변류기 · 몰드타입 PT · CT · SA · 콘덴서 · MCCB · 에폭시 표면 · 철심부 | 부품 하나를 통째로 그리면 되는 `WHOLE_OBJECT` 계열이라 단위 논란이 없다 |

이 30장은 **최종 데이터셋을 대표하려는 표본이 아닙니다.**
`현재 만든 규칙을 여러 라벨러가 실제로 동일하게 적용하는가` 를 확인하는 **가이드 검증용 시험셋**입니다.

### 2단계로 갑니다

```
1차 시험 30장  ->  핵심 경계·단위 검증  ->  규칙 수정  ->  지침서 v2
                                                            |
                        2차 확인 (WHOLE_OBJECT 포함)  <------+
                                    |
                                    v
                            400장 본 seed 라벨링
```

WHOLE_OBJECT 계열은 **1차 결과에서 문제가 드러난 규칙만** 2차 시험셋에 넣습니다.
지금 미리 몇 장을 끼워 넣으면 "왜 이 장들인가"에 대한 표집 근거를 또 만들어야 합니다.

## 0. 시작 전에

- **모르면 그리지 마세요.** 추측한 박스 하나가 규칙 전체를 흔듭니다.
  애매하면 **Skip** 하고 검수 목록으로 넘기면 됩니다. Skip 은 잘못이 아닙니다.
- **박스가 없는 것과 판별 불가는 다릅니다.**
  대상이 정말 없으면 빈 채로 두고, 있는 것 같은데 판단이 안 서면 Skip 합니다.
- 열화상에는 FLIR 화면표시(온도 수치·컬러바·시각·측정 상자 선)가 찍혀 있습니다.
  **그건 부품이 아닙니다.** 표시에 가려 부품을 못 알아보겠으면 Skip 합니다.

## 0-1. 부품을 못 알아보겠을 때 — 이것도 정당한 Skip 입니다

열화상은 색과 각인이 사라져서, **전기설비를 모르면 부품을 구분할 수 없습니다.**
이건 여러분의 잘못이 아니라 자료의 성질입니다. 다음 순서로 하세요.

```
1. 자기 반의 참조 카드를 먼저 본다
   reports/labeling/class_reference/<반이름>.md
   가이드의 색상 박스 사진이 어느 것이 무슨 부품인지 알려줍니다.

2. 같은 장면의 실화상을 본다
   data/labeling/draft/trial/reference_rgb/<case_id>_rgb.jpg
   30장 중 22장에 있습니다. 박스는 열화상에 그리되, 무엇인지는 실화상으로 확인합니다.

3. 그래도 모르겠으면 Skip 하고 사유를 'unknown_part' 로 적는다
```

**추측해서 그리지 마세요.** 틀린 박스 하나가 규칙 검증 전체를 흐립니다.

### Skip 사유를 반드시 나눠 적어 주세요

작업 폴더의 `skip_log.csv` 에 기록합니다.
셋은 고치는 방법이 완전히 다릅니다.

| 사유 | 언제 | 우리가 할 일 |
|---|---|---|
| `rule_unclear` | 무엇인지는 알겠는데 **어디까지 그릴지** 모르겠다 | 규칙을 고친다 |
| `not_visible` | 가려지거나 잘려서 **안 보인다** | 규칙대로 Skip 이 정답. 고칠 것 없음 |
| `unknown_part` | **무슨 부품인지 모르겠다** | 참조 카드를 보강하거나 교육이 필요하다 |
| `other` | 위 어디에도 안 맞는다 | 메모를 보고 판단한다 |

`unknown_part` 가 많이 나오는 것은 **규칙 문제가 아니라 자료 문제**입니다.
숨기지 말고 그대로 적어 주세요. 그래야 맞는 것을 고칩니다.

### Skip 기록 방법 — 딱 한 곳에만 적습니다

`skip_log.csv` 에 한 줄씩 적습니다. **파일을 따로 만들거나 표시를 남길 필요 없습니다.**

| 열 | 무엇을 적나 |
|---|---|
| `annotator` | 본인 이름 (작업 폴더 이름과 같게) |
| `case_id` | 이미지 이름 (`A08`, `B01_작은객체` 등) |
| `scope` | `image` 또는 `object` — 아래 설명 |
| `skip_reason` | `rule_unclear` / `not_visible` / `unknown_part` / `other` |
| `class_if_known` | 무슨 클래스인지는 알겠으면 적고, 모르면 비워 둡니다 |
| `note` | 무엇이 막혔는지 한 줄. **이게 가장 중요합니다** |

#### scope — 한 장 전체인가, 일부인가

| scope | 언제 | 그 장을 어떻게 다루나 |
|---|---|---|
| `image` | **이 장 전체를 못 하겠다** | 일치도 비교에서 **뺍니다** |
| `object` | **일부만 못 하겠다.** 나머지는 그렸다 | 그린 것끼리 **그대로 비교합니다** |

`object` 로 적었으면 **아는 것은 그리고 저장**하세요. 모르는 것만 빼면 됩니다.

#### 적는 예

```
annotator,case_id,scope,skip_reason,class_if_known,note
홍길동,A08,object,unknown_part,,왼쪽 원통이 변압기인지 PT인지 모르겠음
홍길동,B02_작은객체,image,not_visible,,화면이 흐려 아무것도 못 알아보겠음
홍길동,A12,object,rule_unclear,케이블헤드,엘보가 붙어 있어 어디까지인지 모르겠음
```

#### 빈 라벨과 Skip 은 다릅니다

| 상황 | 어떻게 |
|---|---|
| 그릴 대상이 **정말 없다** | 라벨 파일을 **빈 채로 저장**. skip_log 에 적지 않음 |
| 있는 것 같은데 **모르겠다** | skip_log 에 적음 |

이 둘을 섞으면 "대상이 없는 장면"과 "판단이 안 된 장면"이 구분되지 않아,
나중에 무엇을 고쳐야 할지 알 수 없게 됩니다.

### 한 반에서 구분할 클래스는 많지 않습니다

28종 전부를 외울 필요가 없습니다. **자기 반에서 그리는 것은 1~5종뿐**입니다.

## 2. 무엇을 "하나"로 셀 것인가 — 클래스마다 다릅니다

같은 "접촉부"라도 세는 단위가 다릅니다. **이게 이 프로젝트에서 가장 많이 틀리는 부분입니다.**

| 클래스 | 세는 단위 |
|---|---|
| 몰드변압기 접촉부 | **접속점 하나하나.** 볼트로 조인 자리마다 박스 1개 |
| 변류기 접촉부 | **접속점 하나하나.** 위와 같음 |
| MCCB 접촉부 | **한쪽 단자군 전체를 하나로.** 차단기 한 대에 좌 1개 · 우 1개 |
| 케이블헤드 · 그 밖 부품 | **부품 하나를 통째로** |
| LBS 1·2차측 접촉부, 변압기 접촉부, 분기 접촉부, VCB 접촉부, 인입선로 접촉부, CT 접촉부 | **아직 정해지지 않았습니다. 이번 시험에서는 그리지 마세요** |

> 몰드변압기 접촉부와 MCCB 접촉부는 정반대입니다.
> 앞은 볼트마다 쪼개고, 뒤는 한쪽을 통째로 묶습니다. 헷갈리면 이 표를 다시 보세요.

## 3. 박스를 어디까지 그리는가

### 공통 원칙
**보이는 픽셀을 감싸는 가장 작은 사각형.** 여백을 남기지 않고, 잘라내지도 않습니다.
사진이 기울어져 있어도 박스는 화면 기준 수평·수직으로 그립니다.

### 케이블헤드

```
포함  상단 금속 단자부터 리브(주름) 적층부 아래끝까지.
      그 사이의 수직 도체와 캡도 함께 넣습니다.
제외  리브 아래로 내려가는 케이블, 주변 배선, 옆 부스바.
      접촉 단자군은 VCB 접촉부로 따로 그립니다.
애매  엘보(꺾인 연결관)가 붙어 있으면 Skip 하여 검수로 넘깁니다.
```

> **엘보에 대해**: 케이블헤드에 엘보가 연결된 경우, 현재 가이드에서 포함 범위가
> 확정되지 않았습니다. **임의로 포함하거나 제외하지 말고 검수 대상으로 분류합니다.**
> "엘보는 빼라"는 규칙이 아닙니다. 아직 정해지지 않은 것입니다.

### 몰드변압기 접촉부 · 변류기 접촉부

```
포함  볼트로 조여진 접속 지점 하나하나. 접속점마다 박스 하나.
제외  본체(에폭시 표면·변류기)와 거기서 이어지는 도체.
애매  접속점이 겹쳐 몇 개인지 셀 수 없으면 Skip 합니다.
```

### MCCB 접촉부

```
포함  차단기 한 대의 좌측 단자군 전체를 세로로 한 박스,
      우측 단자군 전체를 또 한 박스.
제외  개별 단자·볼트마다 따로 그리지 않습니다. 차단기 본체는 MCCB 로 따로 그립니다.
애매  차단기가 조밀해 어느 기기의 단자인지 모르겠으면 Skip 합니다.
```

## 4. 잘린 부품

```
포함  한쪽 변만 잘렸고 무엇인지 알아볼 수 있으면
      보이는 부분만 박스 치고 truncated 표시.
제외  원래 크기의 30% 미만만 보이면 박스를 치지 않습니다.
애매  두 변 이상 잘려 형태를 못 알아보겠으면 Skip 합니다.
```

**30% 는 화면 기준이 아니라 그 부품의 원래 크기 기준입니다.**
같은 반의 안 잘린 다른 사진을 떠올려 "원래 이만한데 이 정도 남았다"로 가늠하세요.
자로 재는 기준이 아니라 눈대중입니다. 애매하면 Skip 하면 됩니다.

## 6. 겹치는 경우

```
포함  서로 다른 물체면 겹쳐 보여도 각각 박스를 칩니다.
      다른 클래스끼리 겹치는 것은 정상입니다.
제외  같은 물체에 박스를 두 개 그리지 않습니다.
      여러 개를 한 박스로 묶지도 않습니다.
애매  같은 물체가 겹쳐 개별 경계를 못 나누겠으면 Skip 합니다.
```

**정상인 겹침 예**
케이블헤드 박스 안에 VCB 접촉부 박스가 들어갑니다. 둘은 다른 클래스라 각각 그립니다.

**잘못된 겹침 예**
케이블헤드 전체에 박스를 치고, 그 안 상단부에 또 케이블헤드 박스를 칩니다.
같은 물체가 두 개로 세어집니다.

**묶으면 안 되는 예**
나란한 애자 세 조가 겹쳐 보인다고 한 박스로 묶습니다.
셋이면 셋을 각각 그리고, 도저히 못 나누겠으면 Skip 합니다.

## 7. 속성 표시

박스마다 해당하면 표시합니다. **서로 다른 항목이니 하나로 뭉치지 마세요.**

| 속성 | 언제 |
|---|---|
| `truncated` | 프레임 밖으로 잘렸지만 무엇인지 알아볼 수 있을 때 |
| `occluded` | 다른 부품에 가려졌을 때 |
| `ignore` | 판별이 안 되거나 경계를 못 나눌 때 (학습에서 제외됨) |

CVAT 에서 입력하는 곳:

- `occluded` — 박스를 고르고 **단축키 `Q`**
- `truncated` · `ignore` — 박스를 고르면 오른쪽에 뜨는 **속성 체크박스**
- 촬영 유형 — 이미지마다 **`촬영유형` 태그**를 하나 달고 값을 고릅니다

이미지마다 촬영 유형도 함께 기록합니다: **클로즈업 / 중거리 / 전체**

> 속성 칸이 보이지 않으면 그리지 말고 **먼저 알려 주세요.** 프로젝트 설정 문제이고,

### 걸린 시간을 적어 주세요 — `time_log.csv`

작업 폴더의 `time_log.csv` 에 **실제로 걸린 시간**을 적습니다.

```
annotator,date,start,end,minutes,cases_done,note
annotator_A,2026-08-28,14:00,14:35,,9,처음이라 지침서를 자주 봄
annotator_A,2026-08-28,15:10,16:05,,21,
```

- 중간에 쉬었으면 **줄을 나눠** 적습니다. 쉰 시간은 빼고 적습니다.
- `start`/`end` 만 적으면 시간은 자동으로 계산됩니다. `minutes` 를 직접 적어도 됩니다.
- `cases_done` 은 그 구간에 **끝낸 장수**입니다.

> **이것은 속도 평가가 아닙니다.** 라벨러를 서로 비교하려는 것이 아닙니다.
> 30장에 얼마나 걸리는지를 모르면 **본 작업 400장의 소요를 추정할 근거가 없습니다.**
> 그래서 "빨리 한 시간"이 아니라 **"실제로 걸린 시간"** 이 필요합니다.
> 오래 걸렸다면 그것은 지침서가 고쳐야 할 부분이라는 뜻입니다.
