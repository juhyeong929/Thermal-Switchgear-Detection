# 인증 대비 — 품질 지표 증거

> 자동 생성 보조 문서 · 수치는 `python scripts/certification_evidence.py` 가 파일에서 집계한다
> 최신 수치: `evidence.csv` · 미충족: `gaps.csv` · 추적성 세부: `traceability.csv`

## 기준은 어디서 왔나

우리가 만든 기준이 아니다. `수배전반_열화상_라벨링_파이프라인.html` 의
**03 Quality Evidence** 절에 적힌 것을 그대로 쓴다.

유사 도메인(산업설비 열화상 객체탐지)에서 **국가 AI 학습데이터 구축사업**
(과학기술정보통신부 · 한국지능정보사회진흥원 NIA) 기준으로 품질 검증을 마친 선례가 있다 —
AI Hub 「열화상 카메라 이미지」(dataSetSn=235). 그 데이터셋의 공식 지표는
**mAP@IoU 0.5 기준값 70% · 실측 83.8%** (EfficientDet-D0)였다.

본 프로젝트는 부품 단위까지 세분화된 더 정밀한 라벨링이므로 그 수치를 **하한선**으로 삼는다.

## 지표 5종

| | 지표 | 측정 방법 | 목표치 |
|---|---|---|---|
| **C-1** | 라벨링 오류율 | 오류 보고 수 / 전체 데이터 수 | 종료 시 0 에 수렴 |
| **C-2** | 라벨러 간 일치도 | mIoU(박스) / Cohen's Kappa(클래스) | **Kappa 0.8 이상** |
| **C-3** | 클래스 균형 | 클래스별 인스턴스 수 분포 | 시드 기준 클래스당 최소 30~50 |
| **C-4** | 검수 이력 | 라벨러·검수자·가이드 개정 기록 | **전량 추적 가능** |
| **C-5** | 모델 성능 (참고선) | mAP@IoU 0.5 | **70% 이상** |

## 이 층의 원칙

**빈 칸을 추정치로 채우지 않는다.** 인증 심사에서 가장 위험한 것은 비어 있는 칸이 아니라
근거 없이 채워 넣은 숫자다. 아직 재지 못한 지표는 `미측정` 으로 두고 **무엇이 있어야
잴 수 있는지**를 `gaps.csv` 에 적는다.

**대체 지표를 본 지표인 척 쓰지 않는다.** 예를 들어 C-2 의 원문은 *라벨러 간* 일치도다.
지금 확보된 `기존 라벨과의 대조`(Kappa 1.000)는 참고값일 뿐 **인증 지표를 대신하지 않는다.**
라벨러 2명 이상이 있어야 성립한다.

### C-2 는 회차별로 읽는다 (2026-09-02 정책)

**v1 pooled Kappa 0.902 는 기준선(baseline)이지 최종 인증값이 아니다.**

```
v1  round 1  A·B·C  반 정보 비공개  CLOSED   pooled Kappa 0.902
v2  round 2  D·E    반 정보 공개    PENDING  미측정
```

두 회차는 **운영조건이 다르므로 합산하지 않는다.** 최종 판단은 v2 의
panel-stratified 결과를 중심으로 한다. 등록부는 `trial_versions.csv` 하나다.

**pooled 값을 단독 근거로 읽지 않는 이유 — 실측**

| 반 | 배포 클래스 | 짝지어진 박스 | Kappa |
|---|---:|---:|---:|
| P9 | 2종 | 68~82 | 1.000 |
| P4 | 5종 | 3~7 | 0.000~0.417 |

짝지어진 박스 90개 중 68개(76%)가 배포 클래스 2종인 P9 에서 나왔다.
즉 0.902 는 사실상 **"P9 에서 MCCB 와 MCCB 접촉부를 구분할 수 있는가"** 의 값이다.

그래서 다음을 **자동 산출·자동 병기**한다 (`agreement.py` · `certification_evidence.py`).

```
pooled Kappa · panel별 Kappa · count agreement · paired coverage · Skip
+ 배포 2종 이하 / 비교 5장 미만 / paired coverage 70% 미만인 반에 주의 문구
```

회차 비교표: `reports/labeling/trial_compare.md` (`scripts/trial_compare.py`)

### C-4 는 닫혔다

검수 대장 5건 전부 서명·판정 완료.

```
REV-001  기존 라벨 승계          PASS   DEC-003
REV-002  정본 라벨 규격 감사      PARTIAL DEC-016
REV-003  정본 격리 20쌍 전수 판정  PASS   DEC-022
REV-004  시험 라벨 차이 판정      PASS
REV-005  학습셋 누수 표본 101쌍   PASS   DEC-018 · DEC-023
```

**사람 이름은 스크립트가 만들어 넣지 않았다.** 검수자가 직접 기재했다.
DEC 문서는 *결정* 의 기록이지 *검수 행위* 의 기록이 아니다 —
심사에서 "이 라벨을 누가 확인했습니까" 에 DEC 번호로는 답할 수 없기 때문에 대장을 따로 둔다.

### 남은 것은 라벨이 쌓여야 성립하는 지표뿐이다

| | 필요한 것 |
|---|---|
| C-1 | 라벨링 진행에 따른 오류율 **추이** (지금은 2시점) |
| C-2 | D·E 회수 → **5인 기반** (현재 3인) |
| C-3 | 시드 400장 라벨링 완료 후 클래스별 인스턴스 실측 |
| C-5 | 규칙 확정 후 베이스라인 학습 + mAP 측정 |
