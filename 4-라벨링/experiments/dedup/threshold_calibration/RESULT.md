> 2026-09-01 · `scripts/dedup_threshold_calibration.py` · OQ-016 후속

## 실험 설계

**독립변수는 코사인 임계값 하나뿐이다.** 임베딩 · 해밍(≤22) · 리더 방식 · 후보쌍 ·
인벤토리 · 반 · 세션 · 카메라 · 정렬 순서 · 동점 처리를 전부 고정했다.
`dedup_d_cluster` 의 함수와 순서 규칙을 그대로 불러 썼다.

**기준선 재현 검증 통과** — cos 0.93 에서 클러스터 **38,957** 로 기존과 정확히 일치.
따라서 이번 실험 안에서의 비교는 성립한다.

### DEC-008 의 0.90 폭주와는 직접 비교할 수 없다

DEC-008 이 기록한 최대 그룹 12,289~19,370장은 **연결요소(union-find) 방식** 수치다.
리더 방식은 연쇄가 구조적으로 생기지 않으므로 애초에 폭주하지 않는다.
**알고리즘이 다르므로 직접 비교 불가**로 기록한다.

### 임계값을 낮춰도 동일 장면을 못 잡는다

| cos | 임계값 이상인 위험 쌍 | 그중 같은 클러스터 |
|---|---:|---:|
| 0.925 | 6 | 1 (17%) |
| 0.920 | 15 | 2 (13%) |
| 0.9175 | 20 | 3 (15%) |
| **0.9155** | **21** | **3 (14%)** |
| 0.9125 | 22 | 4 (18%) |
| 0.910 | 22 | 3 (14%) |

**간선이 생겨도 같은 클러스터가 되는 것은 14~18% 뿐이다.**

리더 방식은 "이미 정해진 대표와 **직접** 비슷할 때만" 붙인다.
두 이미지가 서로 비슷해도 **각자 다른 리더에 붙으면 분리된다.**
연쇄 병합을 막으려고 택한 성질이 여기서는 비용으로 돌아온다.

**즉 문제는 임계값이 아니라 리더 방식의 구조적 성질이다.**

## 0.93 → 0.9155 로 바뀌는 11쌍

| 판정 | 건수 |
|---|---:|
| SAME_SCENE (원하는 병합) | **3** |
| DIFFERENT_SCENE (과병합) | **8** |

얻는 것 3, 치르는 것 8이다. 게다가 바뀐 8건 중 3건(`pair_0047` 0.9118 ·
`pair_0044` 0.9099 · `pair_0058` 0.9077)은 **임계값보다 낮아 직접 간선도 없는 쌍**이다 —
임계값을 낮추면 리더 배치가 달라져 **부수적 병합**까지 생긴다.

## 해석 (판정은 사람이 한다)

| | 조건 | 관측 |
|---|---|---|
| CASE A | capture 증가 · merge 허용 가능 · 폭주 없음 → 변경 후보 | ✕ — capture 13.6% 뿐 |
| **CASE B** | **대형화 또는 merge 급증 → 0.9155 기각** | **부분 해당** — 폭주는 없으나 trade 가 3:8 |
| CASE C | trade-off 가 여러 임계값에서 비슷 → 추가 feature 또는 보수적 유지 | **해당** |

**0.91~0.93 어디에도 sweet spot 이 없다.** capture 는 9~18% 사이를 오가고
false-merge 는 단조 증가한다. 0.9125 가 capture 18.2% 로 가장 높지만
false-merge 10.1% 를 함께 치른다.

## 이 실험이 알려 준 것

임계값 조정은 **OQ-016 의 해결 수단이 아니다.** 남은 선택지는 성격이 다르다.

1. **현행 유지 + 잔여 위험 문서화** — 추정 20% 를 명시하고 지표 해석에 반영
2. **split 단계 제약** — cluster 를 바꾸지 않고, 간선으로 연결된 이미지를 같은 split 에
   두도록 분할 생성기에 제약을 건다 (cluster_id 무수정, 재클러스터링 없음)
3. **feature 교체** — 이번 범위 밖

**어느 것도 이 실험이 결정하지 않는다.**
