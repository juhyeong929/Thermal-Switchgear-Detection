# split 단계 제약 시뮬레이션 — 측정 결과

> 2026-09-01 · `scripts/split_constraint_sim.py` · OQ-016 후속
> **READ-ONLY · SIMULATION ONLY.** 실제 split 파일을 만들지 않았다.

## 설계

클러스터링을 바꾸지 않는다. **노드는 기존 `cluster_id`** 이고, 제약 간선이 서로 다른
클러스터를 이으면 그 클러스터들이 한 덩어리(super-group)가 되어 같은 split 으로 간다.
분할은 `build_splits.assign` 과 같은 규칙 — (반 × 카메라) 층, 그룹 수 기준 70/15/15,
같은 seed.

**S0 가 현행을 재현한다** (69.9/15.0/15.1 · 강제이동 0) — 비교의 기준선이 성립한다.

## 시나리오별 결과

| | 제약 | 덩어리 | 최대 | 비율 (train/val/test) | 강제이동 | 반별 최소 val/test |
|---|---|---:|---:|---|---:|---|
| **S0** | 없음 (현행) | 38,957 | 84 (0.08%) | 69.9 / 15.0 / 15.1 | 0 | 218 / 219 |
| **S1** | 사람 판정 22쌍 | 38,935 | 84 (0.08%) | **70.0 / 14.9 / 15.1** | **143 (0.13%)** | 218 / 219 |
| S2 | 코사인 ≥ 0.9155 | 17,663 | **14,830 (13.9%)** | **79.0 / 8.6 / 12.3** | 23,817 (22.3%) | 305 / **98** |
| S3 | 코사인 ≥ 0.920 | 18,136 | 14,418 (13.5%) | **80.7 / 8.3 / 11.1** | 23,542 (22.1%) | **135** / 177 |
| S4 | 코사인 ≥ 0.925 | 18,763 | 13,160 (12.3%) | 69.9 / **11.3** / **18.8** | 23,161 (21.7%) | **110** / 213 |

### 이동량은 두 가지를 나눠 재야 한다

그룹 수가 바뀌면 층 안의 셔플 결과가 통째로 달라진다. 그래서 단순 비교(`moved_images`)는
**제약의 비용을 과대평가한다** — S1 은 단순 비교로는 28.7% 지만 실제로는 0.13% 다.

`forced_moves` 는 **제약이 강제하는 최소 이동**이다 — 한 덩어리 안에서 현행 split 이
갈려 있을 때 소수파가 다수파로 옮겨져야 하는 양. 위 표는 이 값을 썼다.

## S1 — 실현 가능하다

- 비율 왜곡 **없음** (70.0/14.9/15.1)
- 반별 val/test 고갈 **없음** (218/219 그대로)
- 덩어리 폭주 **없음** (최대 84, 변화 없음)
- 강제이동 **143장 (0.13%)**
- 세션 교차 174 → 174 (변화 없음)

**CASE A 조건을 전부 만족한다.**

## S2~S4 — 기각

세 시나리오 모두 **최대 덩어리가 12~14%(13,160~14,830장)로 폭주**하고
**val 이 8.3~11.3% 로 붕괴**한다. 강제이동도 22% 대다.

이것은 클러스터 폭주와 성격이 다르다 — 클러스터를 만든 것이 아니라
**split 제약 그래프가 거대 연결요소를 만든** 것이다. 그러나 결과는 같다:
분할이 목표 비율을 지킬 수 없게 된다.

**CASE B — 자동 임계값 기반 제약은 기각한다.**

## 그러나 S1 은 효과가 거의 없다 — 실현 가능성과 효과는 다르다

S1 이 제약하는 것은 **사람이 판정한 22쌍뿐**이다.

```
제약한 쌍                      22
모집단 추정 동일 시야 쌍     약 8,200
-> S1 이 덮는 비율          0.27%
```

**잔여 위험 20% 중 0.27% 만 처리한다.** 나머지를 덮으려면 더 많은 육안 판정이 필요한데,
8,200쌍을 사람이 보는 것은 현실적이지 않다. 101쌍에 이미 상당한 시간이 들었다.

자동으로 범위를 넓히는 길(S2~S4)은 분포를 파괴한다.
**중간 지점이 없다** — 이것이 이번 시뮬레이션의 핵심 결과다.

## false merge 의 의미가 다르다는 점

클러스터 병합에서는 다른 장면을 하나로 묶는 것이 곧 오류다.
**split 제약에서는 다르다.** 다른 장면이라도 근접 유사하면 train/val/test 에 비슷한
데이터가 걸치는 위험이 생기므로, 같은 split 에 두는 것 자체는 잘못이 아니다.
비용은 오직 **분포 왜곡**(비율 · 반별 고갈 · 이동량)으로 나타난다.

그래서 S2~S4 를 기각하는 근거도 "다른 장면을 묶었다" 가 아니라
**"val 이 8.6% 로 무너졌다"** 다.

## 종합 — CASE C

| | 조건 | 판정 |
|---|---|---|
| CASE A | 비율 유지 · 고갈 없음 · 폭주 없음 · 이동 낮음 → 제약 후보 | S1 만 해당 |
| CASE B | 비율 왜곡 · val/test 소멸 · 폭주 → 기각 | S2 · S3 · S4 |
| **CASE C** | **효과가 미미하거나 관리 비용이 큼 → 현행 유지** | **전체 결론** |

S1 은 안전하지만 위험의 0.27% 만 덮고, 범위를 넓히면 분포가 무너진다.
**현재 cluster split + 임계값 0.93 을 유지하고 잔여 위험을 문서화하는 것**이
이번 측정이 가리키는 방향이다. 다만 **결정은 사람이 한다.**
