# 알려진 한계 (Known Limitations)

해결해야 할 버그가 아니라 **측정해서 알고 있는 한계**다.
각 항목은 무엇을 시도해 봤고 왜 그대로 두는지까지 적는다.
숨기지 않고 지표 옆에 함께 붙이는 것이 이 문서의 목적이다.

---

## KL-1 · 근접 유사 쌍의 split 교차 (OQ-016 · DEC-023)

**무엇**
같은 클러스터가 train/val/test 로 갈라지는 사례는 **0건**이다.
그러나 병합 기준(코사인 0.93)을 아슬아슬하게 넘지 못한 **근접 유사 쌍** 중 일부가
split 을 가로지른다.

**얼마나**

| | 값 |
|---|---:|
| split 을 가로지르는 근접 후보쌍 | 41,184 |
| 육안 판정 표본 | 101쌍 (REV-005) |
| 동일 시야 판정 | SAME_SCENE 20 · NEAR_DUPLICATE 2 |
| **층화 가중 추정 위험** | **약 20%** → 추정 8,200쌍 |

**이 숫자를 오독하지 않는다**
- 전체 데이터의 누수율이 **아니다.** 분모는 근접 후보쌍 41,184 다
- 8,200 은 **쌍**이지 이미지 수가 아니다
- 확정값이 아니라 **101쌍 표본의 층화 가중 추정치**다

**무엇을 시도했나**

| 대안 | 결과 |
|---|---|
| 임계값 하향 0.925~0.910 | 동일 장면 포착 14~18% 뿐 · 과병합 단조 증가 → 기각 |
| split 제약 (사람 판정 22쌍) | 이동 0.13% · 분포 안정. 그러나 위험의 0.27% 만 덮음 |
| split 제약 (자동, 코사인 기준) | 최대 덩어리 12~14% · val 8.3~11.3% 붕괴 → 기각 |

**원인**
리더 방식은 "대표와 **직접** 비슷할 때만" 붙인다. 연쇄 병합(union-find 가 45,721장 중
41,063장을 한 덩어리로 만든 사고)을 막으려고 택한 성질이며, 그 대가로 서로 비슷한 두
이미지가 각자 다른 리더에 붙으면 분리된다.

**지표에 함께 적을 문장**
> 같은 클러스터가 두 split 에 걸친 사례는 0건이다. 다만 근접 유사 쌍 중 약 20%
> (추정 8,200쌍)가 split 을 가로지르므로 **val/test 지표는 이만큼 낙관적으로 나올 수 있다.**

**근거**
`reports/decisions/DEC-023-oq016-closure.md` · `DEC-018` ·
`reports/data_audit/oq016/` · `experiments/dedup/threshold_calibration/` ·
`experiments/dedup/split_constraint_sim/`

## KL-2 · train/val/test 비율 70/15/15 에는 프로젝트 근거가 없다 (OQ-015)

관례값을 기본 정책으로 채택했다. 정본 라벨에서는 69.8/15.0/15.3 으로 구현된다.
**비율 자체의 근거는 확립하지 않았다** — 보고 시 그대로 적는다.

## KL-3 · 라디오메트릭 온도는 전체의 2.4% 에만 있다 (OQ-017)

`pilot/flir.py` 는 수정 없이 동작하지만 IR1 100/100 성공 · IR2 0/100 · IR3 0/100 이다.
온도를 입력으로 쓰는 설계는 2,512장에만 적용된다. 정본 라벨 1,036장은 전부 IR1 이다.
1차 목표가 객체 라벨링이므로 현재 작업의 blocker 는 아니다.

## KL-4 · 선언된 OSD 영역은 가림의 증거가 아니다 (OQ-010)

`우측 컬러바` 영역이 `x >= 0.8375` 로 실제 컬러바(`x >= 0.955`)보다 넓게 선언돼 있다.
**좌표만으로 "OSD 가 가렸다" 고 단정하면 틀린다** — 시험에서 실제로 오분류가 나왔다.
OSD 중첩 측정치(71.7% 등)를 읽을 때도 같은 주의가 필요하다.

## KL-5 · 참고(reference) 등급 라벨은 검증되지 않았다 (DEC-011)

P6·P9 의 3,339박스는 미작업 의심분·이상치·검수 이력 부재로 **정본 승격을 보류**했다.
경계 규칙 검증과 사례 추출에만 쓰고 학습·지표의 기준으로 쓰지 않는다.
1차 시험의 기존 라벨 대조에서도 비교 7장 중 6장이 이 등급이었다.

**[2026-09-02 보강]** 이 등급의 한계가 실측으로 한 번 더 확인됐다. VCB 접촉부 단위
판정을 위해 P6 참고 라벨 표본 15장을 열었더니 **5장이 `PARTIAL_LABELING`**
(보이는 것보다 박스가 적음) 이었다. 장당 접촉부 개수 중앙이 1개였던 이유는
묶어 그려서가 아니라 **덜 그려서**였다 (DEC-024).

## KL-6 · 라벨 대상이지만 배포하지 않는 클래스가 5종 있다 (NQ-13)

**무엇**
`label_status` 는 `가공` 인데 `annotation_unit` 이 `UNKNOWN` 이라 라벨러에게
배포하지 않는 클래스가 있다. 제외(EXCLUDE)도 폐지(RETIRED)도 아니다.

| | 클래스 | 왜 |
|---|---|---|
| 5종 | LBS 1차측 접촉부 · LBS 2차측 접촉부 · 변압기 접촉부 · 인입선로 접촉부 · CT 접촉부 | 정본·참고 통틀어 라벨 실적 0건 — 단위 판정의 좌표 근거가 없다 |

```
labelable(반)    단위 미확정 포함     시드 수요 산정 · 이 반이 무엇을 담고 있는가
deployable(반)   단위 확정만          라벨러에게 실제로 그리라고 배포하는 목록
```

**이 구분을 지워서는 안 된다.** 초판 감사에서 지침서 §1(후보 목록)과 §2(단위 미확정
금지)가 5개 반에서 충돌한 것이 이 두 가지를 코드로 나눠 두지 않았기 때문이다.

**세 상태를 섞지 않는다**

```
제외(EXCLUDE)   물체는 있지만 어떤 반에서도 그리지 않는다   부스바 · 케이블 · ACB 접촉부
폐지(RETIRED)   그 이름의 클래스가 더 이상 없다             분기 접촉부 (DEC-025)
비배포          라벨 대상이지만 단위가 없어 못 그린다        위 5종
```

**언제 풀리나**
시드 라벨링에서 실제 사례가 쌓인 뒤 판정한다. **최초 발생 사례만으로 확정하지
않는다** — VCB 접촉부는 참고 159박스가 있었는데도 좌표만으로 못 갈라 표본 15장을
열고서야 판정했다 (DEC-024 · DEC-027 절차 원칙).

## KL-7 · 현행 배포 가이드로는 class_id 와 제외 근거를 재확인할 수 없다 (DEC-026)

**무엇**
2026-09-02 배포판(PDF)에는 이전 판 HTML 의 `03 REFERENCE — 가공 대상 종합` 표가
없다. 20쪽 전부를 확인했다.

```
새 PDF 에 있는 것   반별 가공대상 목록 · 예시 사진 · 주의 문구 · CVAT 속성 설명
새 PDF 에 없는 것   클래스 번호 체계 · 가공여부 기호(O/!/X) · 근거 열
```

**그래서 무엇이 안 되나**

```
· class_id 가 왜 그 번호인가            (가이드번호 - 1 의 기계적 변환)
· 부스바 · 케이블 · ACB 접촉부가 왜 제외인가
```

**어떻게 관리하나**
근거 문장은 이전 판에서 `classes_v2.ThermalClass.description` 으로 이미 옮겨져 있다.
사람이 읽을 표는 `scripts/build_reference_table.py` 가 스키마에서 재생성한다
(`generated/class_reference_table.md`). **PDF 를 파싱해 복원하지 않는다** —
클래스 번호도 기호도 원문에 존재하지 않으므로 만들면 창작이 된다.

이전 판 HTML 은 워크트리에서 빼고 git 이력에 보존한다. 정본이 둘로 보이지 않게 한다.

**남는 위험**
새 PDF 의 반별 목록과 코드의 `PANEL_CLASSES` 가 어긋나도 자동으로 잡히지 않는다.
PDF 가 이미지 문서(20쪽 · 이미지 191개 · 텍스트 약 1,400자)라 기계 대조가 어렵다.
현재는 사람이 대조한 결과만 있다.
