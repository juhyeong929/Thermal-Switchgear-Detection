# 2026-08-31 — 회수 포맷 확정 (DEC-020)

## DECISION — A안 채택: YOLO 1.1 + CVAT XML 이중 회수

주 포맷은 **YOLO 1.1 유지**. 프로젝트 표준을 바꾸지 않는다. 일치도의 primary input 은
계속 YOLO 이고 `agreement.py` 는 **수정하지 않았다.**
CVAT XML 을 함께 보존해 속성만 별도 경로로 뺀다. **라벨러 작업 방식은 그대로.**

## FACT — 왜 필요했나

YOLO 1.1 한 줄은 `<class_id> <cx> <cy> <w> <h>` 다섯 칸이 전부다. **속성 자리가 없다.**
지침서 7항이 요구하는 `truncated`·`occluded`·`ignore` 와 촬영유형은 YOLO 로만 받으면
회수 시점에 소멸한다. 정본 4,177박스에 속성이 없는 것도 같은 이유다.

## FACT — 속성은 지금 구조로는 애초에 저장되지 않는다

`pilot/cvat_prep.py` 는 라벨을 `"attributes": []` 로 만든다. 그 정의로 프로젝트를 만들면
**라벨러 화면에 truncated 입력 칸 자체가 없다.** A안을 정하는 것만으로는 부족했다.

`occluded` 는 CVAT 내장 필드라 정의 없이도 저장된다(단축키 Q · `<box occluded="1">`).
그래서 커스텀으로 다시 정의하지 않았다.

→ `scripts/cvat_labels_json.py` 추가. `classes_v2` · `labeling_rules` 에서 직접 뽑는다.
생성 결과 rectangle 18 + tag 1, `classes.txt` 사용 클래스 18종과 일치 확인.

## 설계에서 지킨 두 가지

**1. 번호를 가정하지 않는다.** YOLO 1.1 에는 shape id 가 없다. 그래서 XML shape 순서와
YOLO 줄 번호가 같다고 가정하지 않고 (이미지 → 클래스 → 좌표)로 대응을 복원하며,
무엇으로 붙었는지를 `match_method` 로 남긴다. 테스트는 **XML 순서를 일부러 뒤집어** 둔
fixture 로 이것을 검사한다.

**2. 없는 값을 만들지 않는다.** XML 에 `truncated` 가 없으면 열은 두되 **빈 칸**으로
남기고 경고한다. `false` 로 채우면 "잘리지 않았다"는 없는 사실을 만드는 것이다.
선언만 되고 안 쓰인 속성도 열로 만들지 않는다.

매칭 실패는 버리지 않고 양방향 4종을 `attributes_unmatched.csv` 에 전부 적는다.
**매칭 + 실패 = 전체 박스**가 XML·YOLO 양쪽에서 성립하는지를 테스트로 강제한다.

# OQ-001 실증 — MOF반 변압기/변류기는 열화상에서 구분되지 않는다

## FACT (육안 확인)

**열화상 외형만으로 MOF반의 변압기와 변류기를 구분할 수 없다.** MOF 는 PT 와 CT 가
한 함체에 통합된 기기라 프레임 안에 둘을 가르는 시각적 특징이 없다. 라벨러 숙련도
문제가 아니다.

1차 시험이 이것을 그대로 잡아냈다 — Skip 12장 중 9장이 MOF 계열(P4 7 · P3 2)이고
`other` 8건이 전부 같은 문장이다.

## FACT — 정본에서도 그 구분은 이루어진 적이 없다

| 반 | 변류기 | 변압기 | 변류기 접촉부 | 변압기 접촉부 |
|---|---:|---:|---:|---:|
| P3 | 49 | **0** | 178 | **0** |
| P4 | 140 | **1** | 41 | **3** |

본체 99.5% · 접촉부 98.6% 가 변류기다. 과거 라벨러도 한쪽으로 몰아 찍었다는 뜻이고,
**정본의 이 클래스 값은 이미지로 검증할 수 없다.**

RGB 우회도 불가능하다 — 페어 보유율 P3 3.7% · P4 8.0% (IR1 구간뿐, DEC-005).
